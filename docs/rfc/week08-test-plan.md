**2. 애매했던 판단을 남겨요**

표를 채우다 보면 **어느 쪽이든 될 것 같은 항목**이 나와요. 그중 두 개를 골라, 왜 그쪽으로 정했는지 문단으로 씁니다. 다른 쪽을 골랐다면 무엇이 달라졌을지도요.

**3. 이 목록 밖은 어떻게 할지 정해요**

위 15개는 이번 주에 전부 해요. 그 밖에도 내 코드에는 테스트할 만한 것들이 남아 있을 거예요. 그중에서

- **다음에는 하면 좋겠다** 싶은 것 하나
- **앞으로도 안 하겠다** 싶은 것 하나

를 골라, 변경 빈도와 실패 비용을 근거로 이유를 적어요. 전부 테스트하겠다는 계획은 계획이 아니에요.

**이번 단계에서는 테스트 코드를 쓰지 않아요. 설계만 하고, 구현은 2단계부터 해요.**

> 💡 "빨간불이 되면 알게 되는 것"에 _"코드가 잘 돌아간다"_, _"컴포넌트가 렌더된다"_ 같은 답이 나오면 그 항목은 다시 보세요. 그 테스트는 통과해도 보장하는 게 없어요.
