# 서비스 정책

이 서비스가 무엇을 어떻게 동작시키는지 정한 규칙을 모았다. 화면·검색·담기·로그인·주문 전 영역을 다룬다.

읽는 사람은 기획·디자인·QA·개발 모두를 상정한다. 그래서 **사용자가 겪는 결과**로 적고, 구현 방식은 적지 않는다.

- 규칙을 그렇게 정한 이유 → `docs/decisions-week09.md`
- 화면 이동과 흐름 → `docs/rfc/week09-user-flow.md`

---

## 1. 서비스 개요

상품을 둘러보고, 마음에 드는 것을 담아, 로그인한 뒤 주문하는 커머스다.

| 구분      | 내용                                          |
| --------- | --------------------------------------------- |
| 취급 상품 | 30개                                          |
| 카테고리  | 캐주얼 · 패션 · 뷰티·잡화 · 홈 · 디지털 (5개) |
| 회원      | 미리 만들어진 8개 계정. **회원가입 없음**     |
| 결제      | 없음. 주문은 접수까지만                       |

## 2. 화면과 접근 권한

| 화면      | 로그인 필요 | 하는 일                                    |
| --------- | ----------- | ------------------------------------------ |
| 홈        | 아니오      | 배너, 카테고리 바로가기, 인기 상품, 신상품 |
| 상품 목록 | 아니오      | 검색·분류·정렬·페이지 이동, 담기·찜        |
| 로그인    | 아니오      | 로그인                                     |
| 주문서    | **예**      | 담은 상품 확인 후 주문                     |
| 주문 내역 | **예**      | 지난 주문 확인                             |

**로그인을 요구하는 기준**은 "그 화면이 돈이나 개인 기록을 다루는가"다.

- 담기·찜은 아직 사는 게 아니라 **고르는 중**이다. 여기서 로그인을 요구하면 결정하지도 않은 사람을 로그인 화면으로 밀어내 이탈만 만든다.
- 주문서부터는 그 사람에게 귀속되는 주문 기록이 만들어지고, 주문 내역은 이미 만들어진 개인 기록이다. 둘 다 본인만 볼 수 있어야 한다.

로그인이 필요한 화면에 들어가면 **로그인 후 원래 보려던 화면으로 돌아온다.** 처음부터 다시 찾아 들어가게 하지 않는다.

## 3. 홈

| 영역      | 규칙                                                            |
| --------- | --------------------------------------------------------------- |
| 배너      | 1개. 제목·설명·이미지                                           |
| 카테고리  | 5개를 모두 노출. 누르면 그 카테고리가 적용된 상품 목록으로 이동 |
| 인기 상품 | 6개                                                             |
| 신상품    | 6개                                                             |

인기와 신상품은 각각 6개로 고정한다. "더 보기"는 없고, 더 보려면 상품 목록으로 간다.

## 4. 상품 목록

### 4.1 조건 네 가지

| 조건     | 선택지                                      | 기본값 |
| -------- | ------------------------------------------- | ------ |
| 검색어   | 자유 입력                                   | 없음   |
| 카테고리 | 전체 + 5개                                  | 전체   |
| 정렬     | 최신순 · 인기순 · 가격 낮은순 · 가격 높은순 | 최신순 |
| 페이지   | 1쪽당 12개                                  | 1쪽    |

### 4.2 검색

- **브랜드와 상품명**을 함께 찾는다. 둘 중 하나만 걸려도 결과에 나온다.
- 대소문자를 구분하지 않고, 앞뒤 공백은 무시한다.
- 입력을 멈추고 **0.3초 뒤**에 찾는다. 글자마다 찾으면 화면이 계속 흔들린다.
- 검색어를 지우면 조건이 풀린 전체 목록으로 돌아온다.

### 4.3 정렬

| 정렬                 | 기준                 |
| -------------------- | -------------------- |
| 최신순               | 등록일 최신          |
| 인기순               | 리뷰 수. 같으면 평점 |
| 가격 낮은순 / 높은순 | 판매가               |

### 4.4 페이지

- 1쪽에 **12개**를 보여준다.
- 조건을 바꿔 결과가 줄어들어 **지금 쪽이 사라지면 1쪽으로 되돌린다.** 빈 화면을 보여주지 않는다.
- 주소를 직접 고쳐 없는 쪽(0쪽, 음수)을 넣어도 1쪽으로 본다.

### 4.5 조건은 주소에 남는다

검색어·카테고리·정렬·페이지는 모두 주소에 기록된다. 그래서 이 네 가지가 성립한다.

- 링크를 복사해 보내면 상대도 **같은 조건의 화면**을 본다
- 새로고침해도 조건이 유지된다
- 뒤로 가기를 누르면 **직전 조건**으로 돌아간다
- 기본값(전체·최신순·1쪽)은 주소에 붙이지 않아 주소가 짧게 유지된다

### 4.6 결과가 없을 때

조건에 맞는 상품이 0개면 그 사실을 분명히 알린다. 목록 자리를 비워두지 않는다.

## 5. 담기와 찜

| 항목   | 규칙                                  |
| ------ | ------------------------------------- |
| 담기   | 한 번 누르면 담기고, 다시 누르면 뺀다 |
| 찜     | 같은 방식으로 켜고 끈다               |
| 로그인 | 필요 없음                             |
| 표시   | 헤더에 각각 개수를 항상 보여준다      |
| 수량   | 없음. 상품당 1개로 본다               |

**보관 범위** — 담은 것과 찜한 것은 **지금 쓰는 탭에서만** 유지된다. 탭을 닫으면 사라지고, 다른 탭이나 다른 기기와 공유되지 않는다.

로그인해도 서버에 저장되지 않는다. 그래서 **비로그인으로 담아둔 것과 로그인 계정의 목록을 합치는 규칙은 없다.** 서버에 담긴 목록이 아직 없기 때문이다.

## 6. 로그인과 로그아웃

### 6.1 로그인

- 이메일과 비밀번호로 한다.
- **로그인 상태는 1시간 유지**된다. 1시간이 지나면 다시 로그인해야 한다.
- 자동 로그인, 로그인 유지 연장, 비밀번호 찾기는 없다.

| 실패                   | 사용자가 보는 것                                   |
| ---------------------- | -------------------------------------------------- |
| 이메일·비밀번호 불일치 | 로그인 화면에 실패 안내. 입력한 내용은 그대로 남음 |
| 서버 오류              | 잠시 후 다시 시도해 달라는 안내                    |

**로그인 실패 사유를 나눠 알려주지 않는다.** 없는 이메일인지 비밀번호가 틀린 것인지 구분해 알리면 어떤 이메일이 가입돼 있는지가 드러난다.

### 6.2 로그인 상태 표시

헤더에서 항상 알 수 있다.

| 상태      | 헤더                              |
| --------- | --------------------------------- |
| 로그인 전 | 로그인                            |
| 로그인 후 | 주문 내역 · `{이름}님` · 로그아웃 |

화면이 뜨는 첫 순간부터 정확한 상태를 보여준다. 로그인했는데 "로그인" 버튼이 잠깐 보였다 바뀌는 일은 없어야 한다.

### 6.3 로그인한 채로 로그인 화면에 들어오면

**로그인 화면을 그대로 보여준다.** 홈이나 다른 화면으로 되돌리지 않는다.

주소를 직접 입력했거나 뒤로 가기로 돌아온 경우인데, 되돌리면 사용자가 의도한 이동을 막는 셈이 된다. 다른 계정으로 로그인하려는 경우도 여기에 해당한다.

### 6.4 로그인이 풀렸을 때

| 구분                       | 안내                                               |
| -------------------------- | -------------------------------------------------- |
| 아직 로그인한 적 없음      | 안내 없이 로그인 화면                              |
| 로그인했었는데 시간이 지남 | **"세션이 만료되었습니다. 다시 로그인해 주세요."** |

둘을 구분하는 이유는 사용자가 할 일이 다르기 때문이다. 전자는 처음 로그인하면 되고, 후자는 "내가 뭘 잘못했나"를 알아야 한다.

**언제 알게 되나** — 시간이 지났다고 화면이 저절로 바뀌지는 않는다. 로그인이 필요한 일을 하려는 순간에 알게 된다.

| 하려던 일                  | 결과            |
| -------------------------- | --------------- |
| 주문서·주문 내역 화면 열기 | 로그인 화면으로 |
| 주문 내역 불러오기         | 로그인 화면으로 |
| 주문 넣기                  | 로그인 화면으로 |

다시 로그인하면 **보고 있던 화면으로 돌아온다.**

### 6.5 로그아웃

로그아웃하면 **담은 것과 찜한 것을 모두 비운다.**

한 대의 기기를 여러 사람이 쓸 수 있고, 로그아웃은 "이제 내가 아니다"라는 선언이다. 이전 사람이 무엇에 관심 있었는지가 다음 사람에게 보이면 안 된다.

대가는 잠깐 로그아웃했다 돌아온 사람도 목록을 잃는다는 것이다. 노출되는 쪽을 더 무겁게 봤다.

**로그아웃에 실패하면 아무것도 바꾸지 않는다.** 로그인 상태와 담은 목록을 그대로 두고 다시 시도하게 한다. 서버에서 로그인이 풀리지 않았는데 화면만 로그아웃된 것처럼 보이면, 사용자는 나갔다고 믿지만 실제로는 나가지 않은 상태가 된다.

## 7. 주문

### 7.1 주문 방법

담은 상품이 그대로 주문 대상이 된다. 별도로 고르는 단계는 없다.

| 항목        | 규칙                              |
| ----------- | --------------------------------- |
| 대상        | 담아둔 상품 전부                  |
| 수량        | 상품당 1개 고정. 조절할 수 없음   |
| 배송지·결제 | 입력하지 않음                     |
| 부분 주문   | 없음. 전부 주문하거나 하지 않거나 |

빈 장바구니로 주문서에 들어가면 주문 버튼을 누를 수 없고, 상품을 담으러 가는 안내를 보여준다.

### 7.2 주문 후

주문에 성공하면 **담은 목록을 비우고** 주문 내역으로 이동한다.

비우지 않으면 주문서에 다시 들어갔을 때 같은 상품이 담겨 있어 **같은 주문을 또 넣을 수 있다.** 헤더 개수도 실제와 어긋난다.

**찜한 목록은 그대로 둔다.** 찜은 사겠다는 뜻이 아니라 관심 표시라, 하나 샀다고 관심이 사라지지 않는다.

주문에 실패하면 담은 목록을 그대로 둔다. 실패했는데 목록까지 잃으면 처음부터 다시 담아야 한다.

### 7.3 주문 내역

최근 것부터 보여주며 한 건마다 네 가지를 표시한다.

| 항목     | 표시                                    |
| -------- | --------------------------------------- |
| 주문번호 | `o1`                                    |
| 상품     | 상품 코드. 3개 이상이면 앞 2개 + `외 N` |
| 수량     | 주문한 상품 개수의 합                   |
| 주문일시 | 한국 시각 기준 `2026-09-01 20:02`       |

**상품 이름과 금액은 보여주지 않는다.** 주문 기록에 남지 않고, 지금 상품 정보를 가져다 붙이면 주문 이후 이름이나 가격이 바뀌었을 때 실제 주문과 다른 내용을 보여주게 된다.

주문이 하나도 없으면 상품을 둘러보라는 안내를 보여준다.

### 7.4 주문 취소·환불

없다.

## 8. 공통 규칙

### 8.1 기다림

| 상황                       | 사용자가 보는 것                                               |
| -------------------------- | -------------------------------------------------------------- |
| 상품 목록을 처음 열 때     | 실제 목록과 같은 크기의 자리 표시. 화면이 갑자기 늘어나지 않게 |
| 조건을 바꿔 다시 불러올 때 | 이전 목록을 유지한 채 갱신 중임을 표시                         |
| 버튼을 눌러 처리 중일 때   | 버튼 문구가 "…중"으로 바뀌고 다시 눌리지 않음                  |

조건을 바꿀 때 목록을 지웠다가 다시 채우지 않는다. 화면이 비었다 차면 어디를 보고 있었는지 잃는다.

### 8.2 실패

| 상황                         | 사용자가 보는 것                               |
| ---------------------------- | ---------------------------------------------- |
| 처음 불러오기 실패           | 실패 안내와 다시 시도 버튼                     |
| 갱신 실패 (이전 목록이 있음) | **이전 목록을 유지**하고 갱신 실패만 따로 알림 |
| 네트워크 끊김                | 연결을 확인해 달라는 안내                      |

이미 보고 있던 내용은 갱신에 실패했다고 지우지 않는다.

### 8.3 주소를 직접 고쳤을 때

| 입력                                | 결과                    |
| ----------------------------------- | ----------------------- |
| 없는 카테고리·정렬                  | 조건에 맞지 않다는 안내 |
| 0쪽·음수 쪽                         | 1쪽으로                 |
| 결과보다 큰 쪽 번호                 | 1쪽으로                 |
| 로그인 후 돌아갈 곳에 **외부 주소** | 무시하고 홈으로         |

로그인 후 돌아갈 주소로 외부 사이트를 넣어도 그쪽으로 이동하지 않는다. 이 서비스 안의 화면으로만 돌아간다.

## 9. 접근성

- 모든 버튼·링크·입력에 키보드로 닿을 수 있고, 지금 어디에 있는지 테두리로 보인다.
- 담기·찜 버튼은 지금 켜져 있는지 아닌지를 보조기기가 읽을 수 있다.
- 주문 내역 표는 열 이름과 행 이름을 함께 읽어 준다.
- 실패 안내는 화면에 뜨는 즉시 읽힌다.
