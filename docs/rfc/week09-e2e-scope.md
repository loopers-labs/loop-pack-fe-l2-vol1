# Week 09 E2E 범위 부록 RFC

## 문서 역할

이 문서는 [Week 09 구현 RFC](./week09-implementation.md)의 E2E 부록이다.
이벤트 스키마, 시드 로그 분석, E2E 포함·제외 결정과 실행 증거의 단일 기준으로
사용한다.

| 항목               | 값          |
| ------------------ | ----------- |
| 상태               | 초안        |
| 현재 범위          | 골격만 작성 |
| E2E 구현 가능 여부 | 불가        |
| 사용자 범위 확인   | 미완료      |

## 운영 규칙

- A~C절을 사용자와 확정하기 전 E2E 코드를 작성하지 않는다.
- 이벤트 수가 아닌 고유 세션을 기준으로 집계한다.
- 인증은 필수이며, 인증 외 E2E는 최대 2개다.
- 포함 시나리오의 단언과 최종 범위는 사용자가 직접 결정한다.
- RFC에 없는 E2E 시나리오는 구현하지 않는다.
- D·E절에는 긴 원문 대신 명령, 결과, artifact 위치와 관찰을 기록한다.

## A. 이벤트 스키마

상태: **결정**

### 이름 규칙

이벤트 이름은 시드 로그와 동일한 snake_case를 사용해 매핑 표가 필요 없게 한다.

| 항목                 | 결정                      | 근거                     |
| -------------------- | ------------------------- | ------------------------ |
| 이벤트 이름 형식     | 시드 로그와 동일 이름     | Stage 3 매핑 비용 최소화 |
| 공통 프로퍼티        | `sessionId`·`ts`·`device` | 시드 공통 필드와 일치    |
| 사용자 identity 표현 | `identify(user.id)`       | 이벤트마다 복사하지 않음 |
| 발생 시각 표현       | 발생 시점 ISO 8601 UTC    | track 시점 평가          |

### 공통 프로퍼티

| 프로퍼티    | 타입                               | 생성 시점                           | 개인정보 여부 |
| ----------- | ---------------------------------- | ----------------------------------- | ------------- |
| `sessionId` | `s_<uuid>` 문자열                  | 탭 단위 sessionStorage, 메모리 폴백 | 아니요        |
| `ts`        | ISO 8601 UTC 문자열                | 이벤트 발생 시점                    | 아니요        |
| `device`    | `mobile`·`tablet`·`desktop`·`null` | 발생 시점 width 기준                | 아니요        |

### 이벤트 목록

과제 필수 지점을 기준으로 하되, 현재 앱에 없는 화면은 제외 사실과 이유를 남긴다.

| 이벤트              | 발생 조건                                                      | 프로퍼티                             | 구현 여부 |
| ------------------- | -------------------------------------------------------------- | ------------------------------------ | --------- |
| `product_list_view` | 목록 조회 조건 확정마다 1회 (진입·필터·정렬·페이지, 중복 없음) | `category`, `sort`, `page`           | 구현 완료 |
| `cart_add`          | 장바구니에 없던 상품이 담길 때만                               | `productId`                          | 구현 완료 |
| `login_start`       | 로그인 화면 표시 시 1회                                        | `from`                               | 구현 완료 |
| `login_success`     | 로그인 200 후 `identify()` 다음                                | `from`                               | 구현 완료 |
| `login_fail`        | 로그인 제출 실패마다 1회                                       | `reason`                             | 구현 완료 |
| `order_start`       | 주문서에서 주문 가능 장바구니 준비 시 1회 (빈 장바구니 없음)   | `itemCount`, `productIds`            | 구현 완료 |
| `order_complete`    | 주문 201 후 장바구니 정리 전 1회                               | `orderId`, `itemCount`, `productIds` | 구현 완료 |

제외: `product_detail_view`(상세 화면 없음), `category_filter_change`·`sort_change`·`page_change`
(`product_list_view` 재발생으로 대체), `wishlist_add`(과제 필수 지점 아님),
`client_error`(이번 주 범위 밖).

관측된 실제 순서: `product_list_view` → `cart_add` → `login_start` →
`login_fail` → `login_success` → `order_start` → `order_complete`.

### 시드 로그 매핑

이름은 시드와 동일하므로 이벤트 이름 매핑은 필요 없다. 형식 차이만 기록한다.

| 현재 값               | 시드 값       | 정규화 규칙                                   |
| --------------------- | ------------- | --------------------------------------------- |
| `sessionId` 전체 UUID | `s_0a3f` 형태 | `s_` 접두 일치, 분석은 정확 값 단위 세션 집계 |

### A절 완료 조건

- 이름 규칙과 공통 프로퍼티가 확정됐다.
- 필수 행동별 발생 조건과 필드가 결정됐다.
- 시드 로그와 이름 또는 구조가 다르면 매핑이 존재한다.
- 로그인부터 주문까지 이벤트 순서를 예측할 수 있다.

## E. E2E 자가 검증

상태: **Stage 5 이후 작성**

테스트 코드는 변경하지 않고 제품 코드 한 곳만 바꾼다. 각 실험이 끝날 때마다
제품 코드를 원복하고 diff를 확인한다.

| #   | 망가뜨린 곳 | 단일 변경 | 통합 테스트 | E2E    | 실패 메시지 | 원복   |
| --- | ----------- | --------- | ----------- | ------ | ----------- | ------ |
| 1   | 미결정      | 미결정    | 미실행      | 미실행 | 미결정      | 미확인 |
| 2   | 미결정      | 미결정    | 미실행      | 미실행 | 미결정      | 미확인 |
| 3   | 미결정      | 미결정    | 미실행      | 미실행 | 미결정      | 미확인 |

### E절 완료 조건

- 실험이 세 가지 이상이다.
- 통합 테스트로 잡지 못하고 E2E만 잡은 항목이 최소 하나다.
- 살아남은 변경이 있다면 원인과 대응을 기록했다.
- 테스트 코드는 실험 중 바꾸지 않았다.
- 제품 코드와 작업트리에 실험 변경이 남아 있지 않다.
