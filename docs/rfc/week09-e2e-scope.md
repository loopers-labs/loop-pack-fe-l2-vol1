# Week 09 E2E 범위 부록 RFC

## 문서 역할

이 문서는 [Week 09 구현 RFC](./week09-implementation.md)의 E2E 부록이다.
이벤트 스키마, 시드 로그 분석, E2E 포함·제외 결정과 실행 증거의 단일 기준으로
사용한다.

| 항목               | 값          |
| ------------------ | ----------- |
| 상태               | 초안        |
| 현재 범위          | 골격만 작성 |
| E2E 구현 가능 여부 | 불가        |
| 사용자 범위 확인   | 미완료      |

## 운영 규칙

- A~C절을 사용자와 확정하기 전 E2E 코드를 작성하지 않는다.
- 이벤트 수가 아닌 고유 세션을 기준으로 집계한다.
- 인증은 필수이며, 인증 외 E2E는 최대 2개다.
- 포함 시나리오의 단언과 최종 범위는 사용자가 직접 결정한다.
- RFC에 없는 E2E 시나리오는 구현하지 않는다.
- D·E절에는 긴 원문 대신 명령, 결과, artifact 위치와 관찰을 기록한다.

## A. 이벤트 스키마

상태: **결정**

### 이름 규칙

이벤트 이름은 시드 로그와 동일한 snake_case를 사용해 매핑 표가 필요 없게 한다.

| 항목                 | 결정                      | 근거                     |
| -------------------- | ------------------------- | ------------------------ |
| 이벤트 이름 형식     | 시드 로그와 동일 이름     | Stage 3 매핑 비용 최소화 |
| 공통 프로퍼티        | `sessionId`·`ts`·`device` | 시드 공통 필드와 일치    |
| 사용자 identity 표현 | `identify(user.id)`       | 이벤트마다 복사하지 않음 |
| 발생 시각 표현       | 발생 시점 ISO 8601 UTC    | track 시점 평가          |

### 공통 프로퍼티

| 프로퍼티    | 타입                               | 생성 시점                           | 개인정보 여부 |
| ----------- | ---------------------------------- | ----------------------------------- | ------------- |
| `sessionId` | `s_<uuid>` 문자열                  | 탭 단위 sessionStorage, 메모리 폴백 | 아니요        |
| `ts`        | ISO 8601 UTC 문자열                | 이벤트 발생 시점                    | 아니요        |
| `device`    | `mobile`·`tablet`·`desktop`·`null` | 발생 시점 width 기준                | 아니요        |

### 이벤트 목록

과제 필수 지점을 기준으로 하되, 현재 앱에 없는 화면은 제외 사실과 이유를 남긴다.

| 이벤트              | 발생 조건                                                      | 프로퍼티                             | 구현 여부 |
| ------------------- | -------------------------------------------------------------- | ------------------------------------ | --------- |
| `product_list_view` | 목록 조회 조건 확정마다 1회 (진입·필터·정렬·페이지, 중복 없음) | `category`, `sort`, `page`           | 구현 완료 |
| `cart_add`          | 장바구니에 없던 상품이 담길 때만                               | `productId`                          | 구현 완료 |
| `login_start`       | 로그인 화면 표시 시 1회                                        | `from`                               | 구현 완료 |
| `login_success`     | 로그인 200 후 `identify()` 다음                                | `from`                               | 구현 완료 |
| `login_fail`        | 로그인 제출 실패마다 1회                                       | `reason`                             | 구현 완료 |
| `order_start`       | 주문서에서 주문 가능 장바구니 준비 시 1회 (빈 장바구니 없음)   | `itemCount`, `productIds`            | 구현 완료 |
| `order_complete`    | 주문 201 후 장바구니 정리 전 1회                               | `orderId`, `itemCount`, `productIds` | 구현 완료 |

제외: `product_detail_view`(상세 화면 없음), `category_filter_change`·`sort_change`·`page_change`
(`product_list_view` 재발생으로 대체), `wishlist_add`(과제 필수 지점 아님),
`client_error`(이번 주 범위 밖).

관측된 실제 순서: `product_list_view` → `cart_add` → `login_start` →
`login_fail` → `login_success` → `order_start` → `order_complete`.

### 시드 로그 매핑

이름은 시드와 동일하므로 이벤트 이름 매핑은 필요 없다. 형식 차이만 기록한다.

| 현재 값               | 시드 값       | 정규화 규칙                                   |
| --------------------- | ------------- | --------------------------------------------- |
| `sessionId` 전체 UUID | `s_0a3f` 형태 | `s_` 접두 일치, 분석은 정확 값 단위 세션 집계 |

### A절 완료 조건

- 이름 규칙과 공통 프로퍼티가 확정됐다.
- 필수 행동별 발생 조건과 필드가 결정됐다.
- 시드 로그와 이름 또는 구조가 다르면 매핑이 존재한다.
- 로그인부터 주문까지 이벤트 순서를 예측할 수 있다.

## B. 시드 로그 분석

상태: **분석 완료**

### 분석 입력

- 파일: `fixtures/events-30d.jsonl` — 22,427행, 8,000세션, 2026-07-22 ~ 2026-08-20
- 필드 설명: `docs/fixtures/events.md`
- 집계 단위: 고유 `sessionId`
- 파싱 실패: 0행

### 정제 기준

| 대상        | 판정 기준                                                                                                                                                                         | 처리                                           | 근거                                                                                                         |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 봇 후보     | 세션의 모든 이벤트가 `device: null`이고, `ts` 밀리초가 `.000`이며, 01시 UTC에만 발생하고, `product_list_view` 한 건만 남기며 props가 `{category:all, sort:latest, page:1}`로 동일 | 세션 제외 (486세션)                            | 다섯 신호가 같은 486세션에 동시 충족. 사람 이벤트에서 `.000`은 27/21,941, 전환은 0건                         |
| 중복 이벤트 | `sessionId`·`ts`·`name`·`props`가 완전히 같은 행                                                                                                                                  | 첫 건만 유지 (77행 제거)                       | 재전송. 목록·페이지·필터·정렬에서만 발생하고 사용자 행동은 한 번                                             |
| 오류 이벤트 | `client_error`                                                                                                                                                                    | 순위 집계에서 제외하고 실패 비용 판단에만 사용 | 사용자 행동이 아니라 결과. 코드가 `IMAGE_LOAD_FAILED` 하나뿐                                                 |
| 잘못된 필드 | 이벤트별 `props` 키 조합 이탈, 선후 관계 위반                                                                                                                                     | 해당 없음                                      | 키 조합은 이벤트마다 1종. `order_start` 없는 `order_complete`와 `product_list_view` 없는 `cart_add` 모두 0건 |

정제 결과는 22,427행 → 21,864행, 8,000세션 → 7,514세션이다.

### 지표 정의

| 지표      | 정의                                              | 분모                     |
| --------- | ------------------------------------------------- | ------------------------ |
| 세션 수   | 해당 이벤트가 1회 이상 발생한 고유 `sessionId` 수 | 없음. 절대값             |
| 비율      | 세션 수 ÷ 정제 후 전체 세션                       | 7,514                    |
| 이탈률    | 1 − (다음 단계 세션 ÷ 시작 단계 세션)             | 각 행에 시작 단계를 명시 |
| 실패 비용 | 실패했을 때 사용자가 잃는 것과 회복 가능성        | 해당 없음                |

### 필터 전후 비교

| 순위 | 경로                     | 필터 전 세션  | 필터 후 세션  | 순위 변화 |
| ---- | ------------------------ | ------------- | ------------- | --------- |
| 1    | `product_list_view`      | 8,000 (100%)  | 7,514 (100%)  | 없음      |
| 2    | `product_detail_view`    | 4,656 (58.2%) | 4,656 (62.0%) | 없음      |
| 3    | `category_filter_change` | 3,056 (38.2%) | 3,056 (40.7%) | 없음      |
| 4    | `page_change`            | 1,756 (21.9%) | 1,756 (23.4%) | 없음      |
| 5    | `cart_add`               | 1,309 (16.4%) | 1,309 (17.4%) | 없음      |
| 6    | `sort_change`            | 943 (11.8%)   | 943 (12.5%)   | 없음      |
| 7    | `login_start`            | 644 (8.1%)    | 644 (8.6%)    | 없음      |
| 8    | `login_success`          | 586 (7.3%)    | 586 (7.8%)    | 없음      |
| 9    | `wishlist_add`           | 480 (6.0%)    | 480 (6.4%)    | 없음      |
| 10   | `order_start`            | 419 (5.2%)    | 419 (5.6%)    | 없음      |
| 11   | `order_complete`         | 277 (3.5%)    | 277 (3.7%)    | 없음      |

| 13   | `client_error`           | 103 (1.3%)    | 103 (1.4%)    | 없음      |

순위는 바뀌지 않고 분모만 8,000에서 7,514로 줄었다. 이벤트 수로 세도 같은 순위가 나온다. 이 로그에서 정제의 효과는 순위 재배열이 아니라 비율의 신뢰도다. 봇 486세션을 남기면 목록만 보고 전환이 0인 세션이 6.1% 섞여 목록 대비 전환율이 실제보다 낮게 보인다.

### 경로별 판단

| 경로             | 세션 수 | 비율  | 이탈률                | 실패 비용                                                                                                      | E2E 가설  |
| ---------------- | ------- | ----- | --------------------- | -------------------------------------------------------------------------------------------------------------- | --------- |
| 목록 탐색        | 7,514   | 100%  | 82.6% (담기 미도달)   | 낮음. 새로고침으로 회복                                                                                        | 제외 후보 |
| 상세 조회        | 4,656   | 62.0% | 71.9% (담기 미도달)   | 판단 불가                                                                                                      | 화면 없음 |
| 필터·정렬·페이지 | 4,544   | 60.5% | 82.1% (담기 미도달)   | 낮음. URL 재입력으로 회복                                                                                      | 제외 후보 |
| 담기             | 1,309   | 17.4% | 68.0% (주문서 미도달) | 중간. 다시 담을 수 있음                                                                                        | 보류      |
| 위시리스트       | 480     | 6.4%  | 판단 불가             | 판단 불가                                                                                                      | 화면 없음 |
| 로그인           | 644     | 8.6%  | 9.0% (성공 미도달)    | 높음. 실패 121세션 중 52.1%만 재시도에 성공하고, 실패한 세션의 주문 완료는 21.5%로 성공 세션 47.3%의 절반 이하 | 포함 후보 |
| 주문             | 419     | 5.6%  | 33.9% (완료 미도달)   | 가장 높음. 결제 직전 이탈에는 회복 경로가 없음                                                                 | 포함 후보 |
| 클라이언트 오류  | 103     | 1.4%  | 판단 불가             | 낮음. 오류 세션의 주문 완료가 8.7%로 전체 3.7%보다 높아 전환을 막지 않음                                       | 제외 후보 |

빈도 순위와 비용 순위가 어긋난다. 1·2위인 목록과 상세는 실패해도 사용자가 즉시 회복하지만, 10위인 주문은 세션의 5.6%에서만 발생하면서 3분의 1이 완료 없이 끝난다. 로그인은 `login_start` 644건이 모두 담기 이후에 발생하고 `from`이 전부 `cart`여서, 보호 경로 진입의 유일한 관문이다.

### B절 완료 조건

- 정제 기준이 재현 가능하게 설명돼 있다.
- 필터 전후 순위와 변화 이유가 기록돼 있다.
- 모든 비율의 분모가 명시돼 있다.
- 이벤트 수가 아닌 세션 수를 기준으로 순위를 냈다.

## E. E2E 자가 검증

상태: **Stage 5 이후 작성**

테스트 코드는 변경하지 않고 제품 코드 한 곳만 바꾼다. 각 실험이 끝날 때마다
제품 코드를 원복하고 diff를 확인한다.

| #   | 망가뜨린 곳 | 단일 변경 | 통합 테스트 | E2E    | 실패 메시지 | 원복   |
| --- | ----------- | --------- | ----------- | ------ | ----------- | ------ |
| 1   | 미결정      | 미결정    | 미실행      | 미실행 | 미결정      | 미확인 |
| 2   | 미결정      | 미결정    | 미실행      | 미실행 | 미결정      | 미확인 |
| 3   | 미결정      | 미결정    | 미실행      | 미실행 | 미결정      | 미확인 |

### E절 완료 조건

- 실험이 세 가지 이상이다.
- 통합 테스트로 잡지 못하고 E2E만 잡은 항목이 최소 하나다.
- 살아남은 변경이 있다면 원인과 대응을 기록했다.
- 테스트 코드는 실험 중 바꾸지 않았다.
- 제품 코드와 작업트리에 실험 변경이 남아 있지 않다.
