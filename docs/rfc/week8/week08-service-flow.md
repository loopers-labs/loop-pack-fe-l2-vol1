# Week 08 서비스 기획 플로우

> 테스트 방법론을 먼저 선택하면 현재 구현 구조에 맞춘 테스트가 되기 쉬워, 사용자에게 유지되어야 할 서비스 흐름을 먼저 정리했다. 이를 기준으로 각 흐름의 실패 비용과 필요한 실행 경계를 판단해 단위·통합·E2E로 배치했다.

> 이 문서는 Week 08 테스트 설계와 구현의 기준이다. 아래 사용자 흐름이 유지되는지를 기준으로 테스트 대상과 단언을 결정한다.

## 1. 홈 페이지 `/`

- 서비스에 진입하면 인기 상품과 신규 상품을 둘러본다.
- 헤더의 상품 메뉴를 선택해 전체 상품 목록으로 이동한다.
- 헤더에서 위시리스트와 장바구니에 담긴 상품 개수를 확인한다.
- 인기 상품 또는 신규 상품 카드에서 상품 정보와 가격을 확인한다.
- 상품 카드의 위시리스트 버튼을 눌러 관심 상품을 저장한다.
- 상품 카드의 장바구니 버튼을 눌러 구매 후보 상품을 저장한다.
- 카테고리를 선택해 해당 카테고리가 적용된 상품 목록으로 이동한다.
- 상품을 담거나 제거한 뒤 헤더의 위시리스트·장바구니 개수 변화를 확인한다.

## 2. 상품 목록 페이지 `/products`

- 전체 상품 목록에 진입해 상품 수와 상품 카드를 확인한다.
- 검색창에 상품명 또는 브랜드명을 입력해 원하는 상품을 찾는다.
- 카테고리를 선택해 전체, 캐주얼, 패션, 뷰티·잡화, 홈, 디지털 상품으로 범위를 좁힌다.
- 최신순, 인기순, 가격 낮은순, 가격 높은순 중 원하는 정렬 기준을 선택한다.
- 검색어·카테고리·정렬 조건을 바꾼 뒤 갱신된 상품 목록을 확인한다.
- 초기화 버튼을 눌러 적용한 검색 및 필터 조건을 기본값으로 되돌린다.
- 이전·다음 버튼을 눌러 다른 페이지의 상품을 탐색한다.
- 첫 페이지에서는 이전 버튼이, 마지막 페이지에서는 다음 버튼이 비활성화된 상태를 확인한다.

## 3. 상품 카드 조작

- 상품명, 브랜드, 가격, 할인 가격, 배송 정보, 평점 등의 정보를 확인한다.
- 위시리스트 버튼을 눌러 관심 목록에 추가한다.
- 장바구니 버튼을 눌러 구매 후보 목록에 추가한다.
- 이미 담긴 상품의 같은 버튼을 다시 눌러 목록에서 제거한다.
- 카드의 선택 상태와 헤더 개수가 함께 변경됐는지 확인한다.
- 다른 상품을 조작해도 기존에 담아 둔 상품 상태가 유지되는지 확인한다.

## 4. 탐색 조건 유지

- 검색어, 카테고리, 정렬, 페이지를 변경한 뒤 주소창의 URL 변화를 확인한다.
- 현재 URL을 복사해 새 탭에서 열고 같은 조건의 목록이 표시되는지 확인한다.
- 필터가 적용된 목록에서 새로고침한 뒤 검색어·카테고리·정렬·페이지가 유지되는지 확인한다.
- 브라우저 뒤로 가기를 눌러 직전 탐색 조건과 목록으로 돌아간다.
- 브라우저 앞으로 가기를 눌러 이후 탐색 조건과 목록을 다시 확인한다.
- 유효하지 않은 페이지 번호가 담긴 URL로 진입했을 때 첫 페이지로 보정되는지 확인한다.

## 5. 예외 및 상태 처리

- 목록 진입 후 상품 데이터가 표시될 때까지 로딩 상태를 확인한다.
- 필터 변경 중 기존 목록이 사라지지 않고 갱신 상태가 안내되는지 확인한다.
- 검색 결과가 없을 때 "검색 결과가 없습니다" 안내를 확인하고 다른 조건으로 다시 탐색한다.
- 목록 요청에 실패했을 때 오류 메시지와 다시 시도 버튼을 확인한다.
- 다시 시도 버튼을 눌러 정상 목록이 다시 표시되는지 확인한다.
- 기존 목록이 있는 상태에서 갱신에 실패했을 때 기존 목록을 유지한 채 오류를 안내하는지 확인한다.

## 대표 흐름

1. 홈에 진입해 인기 상품과 신규 상품을 둘러본다.
2. 카테고리 또는 상품 메뉴를 선택해 상품 목록으로 이동한다.
3. 카테고리를 선택하고 가격 낮은순으로 정렬한다.
4. 원하는 상품의 장바구니 버튼을 누른다.
5. 헤더의 장바구니 개수가 증가한 것을 확인한다.
6. 새로고침하거나 뒤로/앞으로 이동한 뒤에도 탐색 조건을 유지하며 상품 탐색을 이어 간다.
