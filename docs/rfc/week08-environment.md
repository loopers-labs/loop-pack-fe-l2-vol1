## 1. 분리 근거: 확장성 + 예외 대응

### 확장자 컨벤션이 대다수를 자동 분류한다

이 프로젝트에서 테스트 파일의 확장자는 곧 "DOM이 필요한가"의 강한 신호다:

- `.tsx` → JSX를 쓴다 → 컴포넌트를 렌더한다 → DOM이 필요하다
- `.ts` → JSX가 없다 → 순수 로직·라우트 핸들러 → DOM이 불필요하다

현재 11개 중 8개가 이 컨벤션에 맞아떨어진다. 2단계에서 15개 테스트가 추가돼도, 컴포넌트 테스트는 `.tsx`, 순수 로직 테스트는 `.ts`로 작성하면 **config가 알아서 올바른 환경에 배정**한다. 매번 주석을 붙일 필요가 없다.

### 예외는 주석으로 붙인다 — 양쪽 모두

컨벤션을 벗어나는 경우가 있다:

- **`.ts`인데 DOM 필요**: store 테스트 (zustand persist가 `localStorage`를 쓴다)
- **`.tsx`인데 DOM 불필요**: HeroSection 테스트 (렌더 없이 로직만 검증)

이런 예외에는 파일 최상단에 주석 한 줄로 환경을 덮어쓴다:

```ts
// @vitest-environment jsdom   ← .ts 파일을 jsdom으로 끌어올림
// @vitest-environment node     ← .tsx 파일을 node로 되돌림
```

주석은 config 기본값보다 우선하며, **양방향 모두 작동함을 검증했다** (아래 검증 결과 참조). 순수 주석 방식(기존)에서는 DOM 테스트 5개 전부에 주석이 필요했지만, 하이브리드에서는 **예외 3개만** 주석으로 처리하면 된다.

## 2. 실패 방향의 안전성

환경 분리에서 가장 위험한 실수는 **"DOM이 필요한 테스트가 node에서 돌아 에러 없이 잘못 통과하는 것"**이 아니라, **"DOM이 필요한데 node에서 돌아 터지는 것"이 발견이 늦어지는 것**이다. 하이브리드는 이 방향의 실패를 큰 소리로 알려준다.

### 실수 시나리오별 결과

| 실수 상황                               | 결과                                       | 위험도                            |
| --------------------------------------- | ------------------------------------------ | --------------------------------- |
| `.ts` 테스트인데 DOM 필요, 주석 깜빡    | ❌ `document is not defined` 즉시 에러     | 낮음 — 바로 발견                  |
| `.tsx` 테스트인데 DOM 불필요, 주석 깜빡 | ⚠️ jsdom에서 조용히 돌아감 (낭비지만 통과) | 미미 — 1개 파일, 미세한 시간 낭비 |
| 새 `.ts` 테스트 작성, DOM 불필요        | ✅ 자동으로 node에서 돌음                  | 위험 없음                         |
| 새 `.tsx` 테스트 작성, DOM 필요         | ✅ 자동으로 jsdom에서 돌음                 | 위험 없음                         |

**위험한 방향(.ts + DOM 누락)이 가장 큰 소리로 터진다.** 개발자가 주석을 빼먹어도 `document is not defined` 에러가 즉시 뜨기 때문에, 잘못된 환경에서 테스트가 조용히 통과하는 일이 없다.

반대 방향(`tsx` + node 누락)은 조용한 낭비지만, 빈도가 낮고(HeroSection 1개), 기능이 깨지지 않으며, 시간 차이도 미미하다. 이 위험은 아래 "인지하고 있는 위험"에 적어두었다.

## 3. 양방향 주석 덮어쓰기 검증 결과

config 기본 환경을 `jsdom`으로 임시 변경한 뒤, 두 임시 파일을 돌려 주석이 기본값을 양방향으로 덮어쓰는지 확인했다.

```
✓ 주석 O (@vitest-environment node)  → typeof window === 'undefined' 통과 → node에서 돌음
✓ 주석 X                              → typeof window !== 'undefined' 통과 → jsdom에서 돌음
```

config가 `jsdom`이어도 `// @vitest-environment node` 주석이 우선함을 확인했다. 반대 방향(`node` config → `jsdom` 주석)은 기존 store 테스트들이 이미 증명하고 있다.

> 검증 후 임시 파일 제거, config 원복 완료. 기존 108개 테스트 전부 녹색 확인.

## 4. 인지하고 있는 위험과 대응

| 위험                                 | 내용                                                                   | 대응                                                                                               |
| ------------------------------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `.tsx` + DOM 불필요 케이스 주석 누락 | jsdom에서 조용히 돌아 환경 셋업 시간 낭비 (체크 248 정신과 충돌)       | 새 `.tsx` 테스트가 DOM 없이도 통과한다면 `// @vitest-environment node`를 붙인다는 규칙을 팀에 공유 |
| 확장자 컨벤션 예외 증가              | 2단계에서 store/localStorage 관련 `.ts` 테스트가 늘면 주석 예외도 늘음 | 예외가 많아지면(config 분리 이득이 사라지면) 그 시점에서 방식 재검토                               |

## 5. 환경 셋업 시간 비교 (체크 250)

같은 11개 테스트 파일(108개 테스트)을 config만 바꿔서 세 번 돌렸다. 1회차는 콜드 캐시 영향이 있어 2·3회차 평균을 기준으로 비교한다.

### 측정 결과

| 구성                                 | 회차 | Duration | setup | environment |
| ------------------------------------ | ---- | -------- | ----- | ----------- |

|                                      | 2회  | 953ms    | 474ms | 2.02s       |
|                                      | 3회  | 913ms    | 482ms | 1.94s       |

|                                      | 3회  | 1.29s    | 722ms | 5.42s       |

### 비교 (2·3회차 평균)

| 구성      | environment 셋업 시간 (평균) |
| --------- | ---------------------------- |
| 나눴을 때 | **1.98s**                    |

### 해석

## 6. E2E 테스트 실행 명령 분리

### 결정: `pnpm test` 에서 E2E를 분리한다

E2E(Playwright)는 `pnpm test` 에 포함하지 않고, **별도 명령 `pnpm test:e2e`** 로만 실행한다. `package.json` 의 `test` 와 `test:e2e` 스크립트 분리 구성을 그대로 유지한다.

### 분리 근거

#### 6-1. `pnpm test` 는 로컬에서 자주 실행되는 명령어다

`pnpm test` 는 아래처럼 개발 중 잦은 실행이 일어나는 명령이다.

- 코드 수정 → `pnpm test` / `pnpm test:watch` 로 회귀 확인
- PR 직전 `pnpm check`(`test → lint → typecheck → build`) 체인에 포함

이런 **잦은 실행 명령에 느린 E2E가 끼면 개발 피드백 사이클이 느려진다.**

#### 6-2. 실행 비용이 단위/컴포넌트 테스트와 차원이 다르다

| 항목      | 단위/컴포넌트 (Vitest) | E2E (Playwright)                               |
| --------- | ---------------------- | ---------------------------------------------- |
| 실행 시간 | ms 단위                | 수 초 ~ 수십 초                                |
| 필요 환경 | Node만                 | 브라우저 + production build 서버(`pnpm start`) |
| 안정성    | 결정적(deterministic)  | 타이밍/네트워크 영향으로 흔들림                |

#### 6-3. 목적이 다르다

- `pnpm test` → **개발 피드백용**, 빠르게 실패를 잡기 위함
- `pnpm test:e2e` → **릴리스/PR 검증용**, 전체 흐름이 맞는지 확인

#### 6-4. 현재 설정과 일관된다

이미 프로젝트 구성이 분리를 전제로 하고 있다.

- `vitest.config.ts`: `exclude: [...configDefaults.exclude, 'e2e/**']` 로 E2E 폴더 제외
- `package.json`: `test` 와 `test:e2e` 를 별도 스크립트로 관리

### 운영 가이드

| 상황         | 실행 명령                               |
| ------------ | --------------------------------------- |
| 개발 중      | `pnpm test` / `pnpm test:watch`         |
| PR 직전 / CI | `pnpm test` + `pnpm test:e2e` 각각 실행 |

> CI 전용 통합 명령(예: `test:ci`)이 필요해지면 그때 추가로 검토한다.

## 참고: 검토 후 선택하지 않은 대안

| 대안                            | 선택하지 않은 이유                                                                                                                                          |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **파일별 주석만** (기존 방식)   | DOM 테스트마다 주석을 직접 붙여야 함. 깜빡하면 에러, 테스트가 늘면 부담. 이미 5개에 주석이 있었고 2단계에서 더 늘 예정.                                     |
| **Test Projects config 분리만** | 확장자를 벗어나는 예외(2개 `.ts`+DOM, 1개 `.tsx`+node)를 config의 include/exclude 패턴만으로 처리하려면 예외 파일을 일일이 나열해야 해서 유지보수가 어려움. |
| **`environmentMatchGlobs`**     | Vitest 4에서 제거됨. 사용 불가.                                                                                                                             |
