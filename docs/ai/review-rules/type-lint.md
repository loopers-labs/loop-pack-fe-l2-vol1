# Type and Lint Review Rules

## Rule Sources

- `AGENTS.md`
- `docs/assignments/week-01.md`
- `docs/assignments/week-02.md`

## Review Goal

타입과 린트 경고를 숨기지 않고, 필요한 만큼만 고쳤는지 확인한다.

## Rules

- `pnpm`만 사용한다. `npm`, `yarn`, 다른 lockfile 변경이 있으면 지적한다.
- 새 `any`, 불필요한 `as`, `@ts-ignore`, `eslint-disable`로 타입/린트를 우회하지 않는다.
- 타입 오류는 타입 좁히기, 명시적 타입, 데이터 구조 개선으로 해결했는지 본다.
- 린트 규칙을 비활성화했다면 설계로 해결할 수 없었는지 먼저 지적한다.
- 타입 선언, lint 설정, 의존성 변경은 변경 이유가 드러나야 한다.
- 기존 유틸, 타입, 설정을 먼저 확인했는지 본다. 같은 역할을 새로 만들면 지적한다.
- 이름은 의도를 드러내야 한다. `data`, `temp`, `flag`처럼 역할이 흐린 이름은 지적한다.
- 디버깅 `console` 출력은 남기지 않는다. 필요한 오류 출력은 실패 처리 흐름 안에 있어야 한다.
- 검증 우회는 금지한다. `--no-verify` 사용, hook 회피, 실패한 체크를 숨기는 변경은 지적한다.

## Findings To Prefer

- 결정적 하네스가 잡아야 할 문제를 코드나 문서로만 처리한 경우
- 타입/린트 우회가 실제 버그 가능성을 가리는 경우
- 새 의존성이나 새 유틸 없이 해결 가능한 일을 추가 구조로 푼 경우
- 타입 선언, lint 설정, 의존성 변경의 이유가 diff에서 보이지 않는 경우

## Do Not Flag

- 타입을 설명하기 위해 필요한 좁은 `as const`
- 외부 라이브러리 타입 한계 때문에 근거를 남기고 국소적으로 사용한 assertion
- 실패 리포트 목적의 `console.error`
- 현재 요청 범위 밖의 오래된 코드 냄새

## Review Output

문제는 파일/라인과 함께 적고, 어떤 프로젝트 규칙을 어겼는지 연결한다. 근거가 약한 일반론은 finding으로 쓰지 말고 "근거 부족"으로 표시한다.
