**목록 녹화** (`/api/products?scenario=slow`)

> 이 관찰은 Lighthouse 측정과 별개로, 브라우저 자동화로 `/products`를 직접 조작해 확인했다. 위 재현 조건의 CPU·네트워크 쓰로틀링은 적용하지 않았다(어떤 화면이 나오는지를 보는 관찰이라 쓰로틀링과 무관하고, slow API의 1.5초 지연은 그대로 적용됐다).
>
> **production build 검증**: 사용자 Chrome과 충돌을 피하려고 별도 프로필·디버깅 포트로 격리한 headless Chrome을 새로 띄우고 CDP로 직접 조작해 재확인했다. 이 세션에서 로드된 리소스 24건 중 `hmr-client`·`next-devtools` 마커 0건. 서버는 `pnpm start`(PID 95309, BUILD_ID `zk38Z7Rd-BErHCPrcxXfj`, SHA `e81e7296`)로 0단계 5회 측정과 동일 서버다.

**측정 흔들림 판단**: LCP 5회 범위는 39.8 ms(중앙값의 0.48 %)로 매우 좁아, 이보다 큰 변화만 개선으로 판단한다. FCP는 범위 36.8 ms(6.98 %)로 상대적으로 넓다 — 브라우저 프로필이 매 회차 새로 만들어져 브라우저 캐시로는 설명되지 않으므로 서버 측 워밍으로 보이며, FCP 변화는 이 36.8 ms보다 클 때만 주장한다.
