# 5주차 — 상태 소유권 설계

> 0단계: 코드를 작성하기 전에 이번 화면에 필요한 상태를 분류한다.
> 질문은 "어떤 라이브러리를 쓸까"가 아니라 **"이 상태의 원본은 어디에 있나"**다.

## 상태 · 소유자 · 수명 · 공유 범위 · 선택 이유

| 상태 | 원본 · 소유자 | 수명 | 공유 범위 | 선택 이유 |
| --- | --- | --- | --- | --- |
| 홈·상품 목록 데이터 | 원본: 서버 DB / 소유: TanStack Query 캐시 | 컴포넌트보다 길다 — 페이지 왕복 시 캐시 재사용, 새로고침엔 사라져도 됨 | 앱 전체 — 헤더·목록·추천이 같은 데이터를 봄 | 원본이 서버라 Query로 동기화(소유 아님). 여러 컴포넌트가 같은 목록 → 캐시 공유가 이득, `useState`는 중복요청·race |
| 검색·카테고리·정렬·페이지 | 원본: URL(주소창) / 보관: nuqs | 컴포넌트보다 길다 — 새로고침·앞뒤 이동 후 복원(브라우저 히스토리에 얹힘) | 앱 밖의 남 (링크 받은 사람) | 원본이 URL이라 nuqs. persist한 Zustand도 새로고침은 버티지만, 남에게 링크로 넘기는 건 URL만 가능 → **공유 범위**가 URL을 강제 |
| 장바구니·위시리스트 상품 | 원본: 클라이언트 메모리 / 소유: Zustand | 메모리 세션 — 클라이언트 페이지 이동엔 유지, 새로고침엔 리셋돼도 됨(Basic). 영구는 Advanced A persist | 앱 전체 — 헤더 배지·목록 담기 버튼·위시리스트 페이지가 다 읽음 | 값의 유일한 집이 이 브라우저(비로그인이라 서버 계정 없음)라 클라가 원본. 여러 곳이 읽어 전역 필요 → Zustand + selector. store엔 id만(상품 정보 원본은 Query 캐시). 로그인·서버 동기화 생기면 원본이 서버로 이동 |
| 헤더에 표시하는 개수 | 없음 — 파생값 (장바구니 목록의 `.length`) | 해당 없음 (장바구니 목록을 따름) | 해당 없음 (저장된 값이 아님) | `items.length`로 계산. `count`를 따로 저장하면 담기/빼기 때 둘을 같이 갱신해야 하고 하나만 빠뜨리면 배지가 틀림 → selector로 구독해 바뀔 때마다 재계산 |
| 제출 전 검색어와 일시적인 UI 상태 | 원본: 클라이언트 / 소유: useState (컴포넌트 로컬) | 컴포넌트 언마운트까지 (새로고침·페이지 이동에 사라져도 됨) | 이 컴포넌트 하나 | 이 값을 읽는 건 입력창 하나뿐 → 전역 불필요. 타이핑 중 글자는 로컬, 제출로 확정되면 그 값만 URL(2행)로 승격 |
| 로딩·에러·빈 결과 | 없음 — 로딩·에러는 Query가 관리하는 값을 읽고, 빈 결과는 `data.length === 0`으로 계산 | 해당 없음 (Query 상태를 따름) | 해당 없음 (저장된 값이 아님) | 손코딩의 `isLoading`·`error` 3종을 Query가 대신 관리 → 우리가 저장 안 함. 빈 결과는 에러가 아니라 정상 응답이라 `data.length`로 따로 판단 |

## 분류 근거

**원본이 어디인가**로 갈랐고, 도구는 그 결론을 따라왔다.

- **서버가 원본** → TanStack Query. 서버 응답을 Zustand에 복사하지 않는다. 복사하는 순간 원본과 사본이 갈라지고, 어느 쪽이 진실인지 알 수 없게 된다.
- **URL이 원본** → nuqs. "공유·복원해야 하는가"가 판별 기준이다. 검색 조건은 그렇고, 입력 중인 글자는 아니다.
- **클라이언트가 원본** → Zustand. 서버 API가 없어서가 아니라, **없기 때문에 원본이 여기밖에 없어서** 전역으로 올린다.
- **아무도 소유하지 않음** → 계산한다. 헤더 개수와 로딩·에러·빈 결과가 여기 해당한다.

## 전역으로 올리지 않은 것과 그 이유

- **제출 전 검색어** — 공유 범위가 컴포넌트 하나다. 전역에 두면 이 값을 쓰지 않는 컴포넌트까지 리렌더 대상이 된다.
- **일시적 UI 상태** — 수명이 컴포넌트보다 짧거나 같다. 전역에 두면 언마운트 후에도 남아 다음 마운트를 오염시킨다.
- **헤더 개수** — 파생값이라 저장할 상태 자체가 없다.
- **카테고리 목록** — `HomeResponse`와 `ProductListResponse`에 **둘 다** 들어온다. 중복처럼 보여 전역으로 올리고 싶어지지만, 원본은 서버이고 각 응답의 일부일 뿐이다. 전역에 복사하면 서버 원본을 클라이언트가 소유하는 셈이 된다.
- **`scenario`** (`empty` / `error`) — 제공 API와 상태별 화면을 검증하기 위한 제어값이다. 사용자가 공유·복원할 조건이 아니므로 URL 상태(`ProductListQuery`)와 필터 UI에 넣지 않는다.

## 로그인·서버 동기화가 생기면

위시리스트의 **원본이 서버로 이동**한다. 그러면 지금의 Zustand는 원본이 아니라 사본이 되므로, 장바구니·위시리스트 행은 서버 상태 행으로 옮겨가야 한다. 이때 결정해야 할 것:

- 비로그인 중 담아둔 익명 상태를 **계정 데이터에 합칠지, 버릴지**
- 합친다면 양쪽에 같은 상품이 있을 때의 **충돌 처리**
- 로그아웃 시 계정 위시리스트를 화면에서 **어떻게 걷어낼지**

Basic 범위에서는 서버 mutation과 낙관적 업데이트를 적용하지 않는다.
