# 9주차 — 인증과 계측, 그리고 E2E 범위

보호 경로와 인증 흐름을 만들고, 사용자 행동을 이벤트로 계측하고, 시드 로그를 근거로 **무엇을 E2E로 만들지 정한** 주차다.

이번 주의 결과물은 코드가 아니라 판단이다. 과제가 요구한 것도 "E2E를 몇 개 짰는가"가 아니라 "왜 그것만 짰는가"다.

## 이번 주 결론 — 한눈에

### E2E 3개를 만든다

| #   | 시나리오                                                  | 왜                                                                |
| --- | --------------------------------------------------------- | ----------------------------------------------------------------- |
| 1   | 인증 플로우 (보호 경로 진입 · 세션 만료 · 자격 증명 오류) | 인증이 깨지면 보호 화면과 주문을 아예 검증할 수 없다              |
| 2   | 담기 → 팝업에서 장바구니 이동 → 담은 상품 확인            | 담기가 끊기면 주문을 시작할 수 없다. 팝업·라우팅·상태의 실제 연결 |
| 3   | 장바구니 → 주문 → 주문내역 확인                           | 결제는 됐는데 주문내역에 없으면 큰 CS 비용                        |

빈도 1·2·3·5위인 목록·필터·정렬·페이지는 **안 붙였다.** 8주차 통합 테스트가 이미 덮고 있고 브라우저 경계가 추가되지 않는다.

### 집계에서 나온 것

- 시드 로그 30일 · 22,427 이벤트 · 8,000 세션. 순위는 **세션 기준**으로 셌다.
- 노이즈 세 기준(봇 · 중복 전송 · 오류 이벤트)으로 **8,000 → 7,514세션**.
- **거르기 전후 순위는 바뀌지 않았다.** 세션 기준으로 센 것이 노이즈 방어로도 작동했다.

### 로그 순위만으로 정하면 안 되는 자리

- 시드 로그 2위 `product_detail_view`(4,656세션)는 **이 앱에 상세 화면이 없어** 빠진다. 규모가 작아서 빠진 게 아니다.
- 반대로 빈도가 낮은 인증(8.1%)과 주문 완료(3.5%)는 **실패 비용 때문에** 넣었다.

## 1단계에서 갈렸던 판단

전문은 [`decisions.md`](./decisions.md)에 있다. 결론만 옮긴다.

| 갈림길                            | 정한 것                                                            |
| --------------------------------- | ------------------------------------------------------------------ |
| 복원 경로 파라미터                | `returnUrl` + `toSafeReturnPath()`로 내부 경로만 허용              |
| 보호 경로 범위                    | 주문서 · 주문 내역 · 장바구니 · 위시리스트 · 마이페이지            |
| 로그아웃 시 장바구니 · 위시리스트 | 지우지 않고 **소유자별로 보관**                                    |
| 가드의 쿠키 검증 깊이             | 존재만 확인. 실제 검증은 페이지·API가 맡는다                       |
| 세션을 클라이언트로 넘기는 방식   | 서버가 읽어 내려주고, 로딩 중과 미로그인을 `null` 하나로 안 섞는다 |

## 계측한 이벤트

15개. 이름 규칙은 `오브젝트_행동`이고, 같은 행동에 화면별 다른 이름을 만들지 않는다(위치는 프로퍼티로 구분).

```
product_list_view · category_filter_change · sort_change · page_change
cart_add · cart_remove
wishlist_view · wishlist_add · wishlist_remove
login_start · login_success · login_fail · logout_complete
order_start · order_complete
```

시드 로그에 있지만 이 앱에 없는 것은 `product_detail_view`와 `client_error` 둘이다. 화면과 계측 대상 자체가 없어 빠진다.

계측 지점과 프로퍼티는 [RFC §A](../rfc/week09-e2e-scope.md#a-이벤트-스키마), 그렇게 정한 과정은 [`event-instrumentation-scope.md`](./event-instrumentation-scope.md)에 있다.
