# 5주차 설계 근거 — 상태의 자리

> 도구를 먼저 고르지 않고 "이 상태의 원본(Source of Truth)이 어디인가"를 먼저 정했다.

## 0단계. 상태 소유권 표

| 상태 | 소유자 | 수명 | 공유 범위 | 선택 이유 |
|---|---|---|---|---|
| 홈 데이터(배너·카테고리·인기·신상품) | 서버 · TanStack Query | 캐시 수명(stale 5분 / gc 10분) | 홈 화면 | 원본이 서버에 있음. 화면 값은 스냅샷이라 `setState`로 소유하지 않는다 |
| 상품 목록·totalCount | 서버 · TanStack Query | 캐시 수명(stale 1분) | 목록 화면 | 원본이 서버. 조건별 캐시를 위해 조건을 query key에 반영 |

## 책임을 나눈 기준

- **서버(TanStack Query)**: "서버에 물어봐서 받아오는" 값. 홈·목록. 응답을 Zustand로 복사하지 않는다.
- **URL(nuqs)**: 링크로 공유하거나 새로고침·앞뒤 이동으로 복원돼야 하는 조회 조건. 검색·카테고리·정렬·페이지.
- **전역 클라이언트(Zustand)**: 서버·URL 어디에도 없지만 여러 화면이 함께 보는 비로그인 담기 상태.
- **로컬(useState)**: 한 컴포넌트 수명 안에서만 쓰는 초안·일시 UI.

## staleTime / gcTime 정책

- 홈: 자주 바뀌지 않는 카탈로그성 → `staleTime 5분`, `gcTime 10분`. 재방문 시 재요청 없이 즉시 표시.
- 목록: 조건별 결과라 더 짧게 `staleTime 1분`. 같은 조건 재방문·뒤로가기엔 캐시가 즉시 응답하고, 오래되면 배경 갱신.
- 전역 기본값은 `staleTime 60초`, `retry 1`(mock 500ms 지연 위 과한 재시도 방지).

## store 데이터 형태와 selector 경계

- 형태: `cart` / `wishlist`를 각각 `Record<id, true>`로 둔다. 상품 상세(가격·이름)는 서버 소유라 복사하지 않고 **id만** 담는다.
- selector: 헤더는 `count`(파생)만, 상품 버튼은 `해당 id 포함 여부 + toggle action`만 구독한다. 다른 상품이 담겨도 무관한 카드는 리렌더되지 않는다.
- 개수는 `Object.keys(...).length`로 파생 — 별도 필드로 저장하지 않는다.

## 전역으로 올리지 않은 상태와 이유

- **검색어 초안**: 제출 전에는 SearchForm 로컬. 확정(제출) 시점에만 URL로 승격.
- **로딩·에러**: Query `status`가 이미 소유. 별도 상태로 만들지 않는다.
- **헤더 개수**: 담긴 id에서 계산되는 파생값.

## 로그인·서버 동기화가 생기면

위시리스트의 원본은 서버(계정)로 옮겨간다. 그때 로컬 익명 상태는 (1) 로그인 시 계정 데이터와 병합할지 / 버릴지, (2) 충돌 처리 규칙을 정한 뒤, Zustand의 역할을 "서버 상태로 보내기 전 임시 입력" 또는 순수 UI 상태로 다시 좁혀야 한다.

## 검증 (수동)

- URL 공유/새로고침: `/products?q=스탠리&sort=price-asc&page=2` 복사 → 같은 조건 복원.
- 앞뒤 이동: 카테고리·정렬 변경마다 `history:"push"`로 쌓여 뒤로/앞으로 복원.
- 필터 변경 시 `page` 1로 리셋.
- 홈↔목록 이동 중 헤더 담기 개수 유지(store가 layout 위에 있어 라우팅으로 소실되지 않음).

## AI 협업 표기

- **직접 결정(설계 판단, 근거는 위 표·정책)**: 각 상태를 어느 자리에 둘지, staleTime/gcTime 값, store 데이터 형태(`Record<id,true>`)와 selector 경계, 검색 초안을 로컬로 둔 결정.
- **AI가 작성 후 직접 검토(기계적)**: provider 배선, `fetchJson` 헬퍼·에러 가드, nuqs parser 배선, Zustand 보일러플레이트, 컴포넌트 골격, CSS(5주차 예시 이식).
