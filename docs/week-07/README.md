## 핵심 결과

### 홈 LCP

| 단계                      | 실측 LCP | Lighthouse LCP | 판단                                  |
| ------------------------- | -------- | -------------- | ------------------------------------- |
| Before                    | 662.1ms  | 8,289.6ms      | 기준                                  |
| 렌더링 경계 분리          | 638.9ms  | 8,290.2ms      | Header·`h1`을 첫 flush에 포함해 유지  |
| Hero 이미지 축소          | —        | 2,370.2ms      | 유지                                  |
| preload + `fetchpriority` | 586.2ms  | 2,448.1ms      | Lighthouse LCP가 77.9ms 악화돼 되돌림 |
| Hero 이미지·카피 분리     | 123.2ms  | 2,307.6ms      | 유지                                  |

Hero를 7.5MB JPG에서 179KB WebP로 바꿨고 표시 크기·비율·피사체·문구는 유지했다. 상세한 구간 분해와 개입별 판정은 [LCP 구간 분해](measurement.md#lcp-구간-분해)와 [개입 요약](measurement.md#개입-요약과-다음-병목)에 있다.

### 상품 목록 6상태

| 상태       | 판단      | 개입 또는 유지 이유                                           |
| ---------- | --------- | ------------------------------------------------------------- |
| 최초 진입  | 이미 충족 | 무개입                                                        |
| 갱신 중    | 의도 충족 | 기존 목록 유지 조건 때문에 CLS 0.37은 무개입                  |
| 성공 + 0건 | 이미 충족 | 무개입                                                        |
| 최초 실패  | 이미 충족 | 분기만 정리                                                   |
| 갱신 실패  | 미충족    | 직전 목록 유지 + 흐름 밖 실패 알림으로 개선, CLS 0            |
| 취소       | 관찰 불가 | `AbortSignal`을 실제 fetch에 연결해 취소를 관찰 가능하게 변경 |

관찰하지 않은 상태를 추정으로 고치지 않고, [관찰 → 가설 → 반증 → 최소 변경](measurement.md#관찰--가설--반증--최소-변경) 순서로 판단했다.

### Advanced A — INP

| 항목                | Before  | After           |
| ------------------- | ------- | --------------- |
| 렌더된 카드         | 24장    | 누른 카드 1장   |
| INP 중앙값          | 107.2ms | 35.6ms (`−67%`) |
| processing 중앙값   | 79.26ms | 8.59ms (`−89%`) |
| input delay 중앙값  | 1.04ms  | 0.88ms          |
| presentation 중앙값 | 25.89ms | 25.54ms         |

Profiler에서 `SyncExternalStore` 변경으로 관계없는 카드 23장까지 렌더되는 것을 확인한 뒤 `wishlistIds` 배열 전체 구독을 카드별 boolean 구독으로 좁혔다. 줄어든 총 71.6ms 중 70.7ms가 processing에서 나왔다. 측정 뷰포트는 960 × 929(dpr 1)이고, 카드 24장·필수 계산·즉시 피드백·복수 카드 독립 상태 회귀 4항목은 전부 통과했다. Before SHA `8aa15c5`, After SHA `f50b925`. 절차, 트레이스 6건과 캡처는 [Advanced A — INP 측정 및 개선](advanced-a-inp.md)에 있다.

## 유지·되돌림·무개입

### 유지한 변경

- 홈 렌더링 경계 분리
- Hero 이미지 축소
- Hero 이미지와 카피의 Suspense 경계 분리
- 상품 목록 갱신 실패 UI 분리
- Query의 `AbortSignal`을 실제 fetch에 전달
- Advanced A selector를 배열 전체에서 카드별 boolean 구독으로 축소

### 되돌리거나 개입하지 않은 것

- Hero preload는 Lighthouse LCP가 악화돼 되돌렸다.
- 갱신 중 CLS 0.37은 기존 목록 유지라는 명세 조건과 상충해 원인만 확정하고 개입하지 않았다.
- Advanced B는 선택하지 않았다. Advanced A 하나를 재현·가설·변경·검증까지 수행했다.

## 미충족 및 남은 항목

### Basic에서 발견하고 남긴 것

- RSC가 자기 Route Handler를 HTTP로 호출한다. 과제 명세가 기존 구조와 서버 호출 계수 측정을 요구해 구조를 유지했다.
- 상품 목록은 클라이언트 전용 조회라 초기 HTML에 상품 데이터와 상품 링크가 없다.
- 모바일 Hero는 표시 폭보다 과대한 이미지가 전송된다.
- Hero 개선 뒤 전송량의 다음 병목은 약 2MB의 Pretendard variable font다.

Advanced A는 남은 항목 없이 완료했다.

전체 요구사항의 충족 여부와 남긴 이유는 [체크리스트](checklist.md)에서 확인할 수 있다.
