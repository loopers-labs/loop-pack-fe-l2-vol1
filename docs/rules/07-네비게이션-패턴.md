# 07 — 네비게이션 패턴

## When to read

링크, 라우트 전환, 뒤로 가기, prefetch, URL 상태 복원, 페이지 정규화를 작성하거나 변경할 때 읽는다.

## Source of truth

- Next.js 라우터와 설정: `next.config.ts`, `package.json`
- URL 상태: [`./04-상태-관리.md`](./04-상태-관리.md)

## Rules

### 1. URL은 상태의 원본이다

- 공유·새로고침·앞뒤 이동으로 복원되어야 하는 조건은 URL에 둔다.
- `history: "push"`로 URL 변경 시 각 변경을 앞뒤 이동에서 복원할 수 있게 한다.

| ✅ 올바른 예                       | ❌ 잘못된 예                            |
| ---------------------------------- | --------------------------------------- |
| `?category=fashion&q=stan&page=2`  | 페이지 상태를 로컬 state로만 관리       |
| `history: 'push'`로 검색/필터 변경 | `history: 'replace'`로 뒤로 가기 불가능 |

### 2. 페이지는 양의 정수만 허용한다

- 페이지(page)는 양의 정수만 허용해 그 외 값은 `1`로 정규화한다.
- 검색·카테고리·정렬이 바뀌면 페이지를 1로 돌아간다.

```ts
// ✅ 올바른 예
const pageParser = parseAsInteger
  .withOptions({ clearOnDefault: true })
  .withDefault(1)

// ❌ 잘못된 예
const page = Number(query.page) || 1
```

### 3. prefetch와 hydration 계약을 지킨다

- Next.js의 non-blocking prefetch/hydration 계약을 따르며, metadata와 초기 HTML 계약을 함께 정리한다.
- 필요한 데이터는 서버 컴포넌트에서 prefetch하고, dehydrate/hydrate로 클라이언트에 전달한다.

| 작업               | 위치                             | 주의                   |
| ------------------ | -------------------------------- | ---------------------- |
| 메타데이터         | `page.tsx`/`layout.tsx`          | 동기적, 빠르게         |
| prefetch           | `page.tsx` 서버 컴포넌트         | dehydrate 필요         |
| 클라이언트 hydrate | `providers.tsx` 또는 해당 페이지 | SSR HTML과 불일치 주의 |

### 4. 라우트 전환 중 상태는 유지한다

- 라우트 전환 중 전역 상태(장바구니·위시리스트 등)가 초기화되지 않도록 Header는 root layout에 둔다.
- 라우트 변경 시 unmount되는 컴포넌트의 로컬 상태는 복원되지 않으므로, 복원이 필요하면 URL이나 persist store로 이동한다.

## Verification

- 뒤로 가기, 새로고침, URL 공유 시 상태가 복원되는지 수동으로 확인한다.
- prefetch가 의도한 대로 동작하는지 DevTools로 확인한다.
- 페이지 정규화가 잘못된 URL에도 동작하는지 확인한다.

```bash
pnpm lint
pnpm typecheck
pnpm build
```
