# 06 — 폼 패턴

## When to read

입력 폼, 검색 input, 제출 동작, 폼 유효성 검사, debounce를 작성하거나 변경할 때 읽는다.

## Source of truth

- 입력 검증 라이브러리: `package.json`, `pnpm-lock.yaml`
- 외부 입력 검증 규칙: [`./05-API-패턴.md`](./05-API-패턴.md)
- 접근성: [`17-접근성.md`](17-접근성.md)
- URL 상태: [`./04-상태-관리.md`](./04-상태-관리.md)

## Rules

### 1. 모든 폼 값은 schema로 검증한다

- 외부에서 들어오는 폼 값은 Zod schema로 검증한다.
- 클라이언트에서만 유효성을 검사하지 않고, 서버 경계에서도 동일한 검증을 수행한다.

| ✅ 올바른 예                               | ❌ 잘못된 예                         |
| ------------------------------------------ | ------------------------------------ |
| `searchSchema.safeParse(rawQuery)`         | `rawQuery.trim().length > 0`         |
| route handler에서 `formSchema.parse(body)` | 서버에서 body를 `as FormBody`로 단언 |

### 2. URL 동기화와 입력 초안을 분리한다

- 검색어처럼 URL 상태와 동기화해야 하는 최종 값은 nuqs로 두되, 타이핑 중인 초안은 컴포넌트 로컬 상태로 다루어 매 입력마다 URL이 바뀌지 않게 한다.
- 외부에서 URL이 바뀌면 draft를 재마운트 없이 조용히 따라가고, 자체 debounce는 포커스를 유지한다.
- 제출 전 input 초안은 React 로컬 상태 또는 nuqs로 관리하며, URL 동기화가 필요한 값만 nuqs에 반영한다.

```tsx
// ✅ 올바른 예
function SearchInput() {
  const [q, setQ] = useState(query.q) // 초안
  const [, setQuery] = useQueryStates(productFilterParsers)

  useEffect(() => {
    setQ(query.q) // URL이 외부에서 바뀌면 조용히 따라간다
  }, [query.q])

  const debouncedUpdate = useDebounce((value: string) => {
    setQuery({ q: value, page: 1 })
  }, 300)

  return (
    <input
      value={q}
      onChange={(e) => {
        setQ(e.target.value)
        debouncedUpdate(e.target.value)
      }}
    />
  )
}

// ❌ 잘못된 예: 매 입력마다 URL이 갱신됨
function SearchInput() {
  const [query, setQuery] = useQueryStates(productFilterParsers)
  return (
    <input value={query.q} onChange={(e) => setQuery({ q: e.target.value })} />
  )
}
```

### 3. 폼 컴포넌트는 접근성 계약을 지킨다

- 폼 컴포넌트는 label, error 메시지, focus/invalid 상태의 접근성 속성을 함께 설계한다.
- `htmlFor`/`id`, `aria-invalid`, `aria-describedby`를 연결한다.

| ✅ 올바른 예                                                | ❌ 잘못된 예                           |
| ----------------------------------------------------------- | -------------------------------------- |
| `id="email"` input + `htmlFor="email"` label                | placeholder만으로 label 역할을 대체    |
| `aria-invalid={!!error}` + `aria-describedby="email-error"` | 에러 메시지를 시각적 스타일만으로 표현 |

### 4. debounce는 제어 가능하게 만든다

- debounce delay는 상수로 분리해 테스트와 조정이 가능하게 한다.
- leading/trailing 옵션을 명시적으로 선택하고 이유를 주석으로 남긴다.
- 포커스를 유지하고, 제출 시 pending debounce는 즉시 flush한다.

## Verification

- 폼 제출 시 유효성 검사가 누락되지 않는지 확인한다.
- 접근성 속성(`aria-invalid`, `aria-describedby` 등)이 있는지 확인한다.
- debounce가 의도한 대로 동작하는지 수동 테스트한다.

pnpm lint
pnpm typecheck
