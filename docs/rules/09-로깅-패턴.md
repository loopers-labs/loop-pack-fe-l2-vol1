# 09 — 로깅 패턴

## When to read

콘솔 출력, 에러 추적, 디버깅 로그, 사용자 행동 로깅을 작성하거나 변경할 때 읽는다.

## Source of truth

- ESLint: `eslint.config.mjs`
- 런타임 경계: [`./05-API-패턴.md`](./05-API-패턴.md)

## Rules

### 1. 프로덕션에는 console.log를 남기지 않는다

- lint 규칙이 `console.log`를 감지하도록 한다.
- 개발 중 임시 로그는 머지 전 제거하거나 명시적인 logger 유틸로 교체한다.

| ✅ 올바른 예                                | ❌ 잘못된 예                           |
| ------------------------------------------- | -------------------------------------- |
| `logger.debug('fetchProducts started')`     | `console.log('fetchProducts started')` |
| `logger.error('payment failed', { error })` | `console.error(error)` 후 무시         |

### 2. 에러는 삼키지 않는다

- 에러는 처리하거나, 사용자에게 보여주거나, 상위 계층으로 명시적으로 전파한다.
- `catch` 블록에서 아무것도 하지 않는 것은 금지한다.

```ts
// ✅ 올바른 예
try {
  await submitOrder(payload)
} catch (error) {
  logger.error('order submission failed', { error })
  showToast('주문 제출에 실패했습니다. 다시 시도해주세요.')
}

// ❌ 잘못된 예
try {
  await submitOrder(payload)
} catch (e) {
  // 아무것도 안 함
}
```

### 3. 민감 정보는 로그에 남기지 않는다

- 사용자 행동 로깅이 필요하면 별도 logger 유틸을 두고, 민감 정보(비밀번호, 토큰, 개인 식별 정보)가 노출되지 않도록 한다.
- 로깅 payload는 scrubbing 함수를 거친다.

| ✅ 올바른 예                                | ❌ 잘못된 예                                    |
| ------------------------------------------- | ----------------------------------------------- |
| `logger.info('login', { userId: user.id })` | `logger.info('login', { user })` 전체 객체 노출 |
| scrub 후 query string 로깅                  | access token이 포함된 URL 그대로 로깅           |

### 4. 로그 레벨을 의도에 맞게 사용한다

| 레벨    | 사용                               |
| ------- | ---------------------------------- |
| `debug` | 개발/진단용 상세 흐름              |
| `info`  | 사용자 행동, 비즈니스 이벤트       |
| `warn`  | 복구 가능한 문제, deprecated 사용  |
| `error` | 복구 불가능한 오류, 즉시 대응 필요 |

## Verification

- `pnpm lint`에서 `console.log` 관련 경고가 발생하지 않는지 확인한다.
- 에러가 무시되지 않고 처리 흐름에 포함되는지 확인한다.
- 민감 정보가 로그에 노출되지 않는지 확인한다.

```bash
pnpm lint
pnpm typecheck
```
