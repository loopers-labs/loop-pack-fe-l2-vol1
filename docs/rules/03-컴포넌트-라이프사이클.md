# 03 — 컴포넌트 라이프사이클

## When to read

React 컴포넌트, Hook, 렌더링 흐름, effect, memoization을 작성하거나 변경할 때 읽는다.

## Source of truth

- React와 JSX 정적 규칙: `eslint.config.mjs`
- React 및 관련 패키지: `package.json`, `pnpm-lock.yaml`

## Rules

### 1. 먼저 순수하고 예측 가능하게 작성한다

- 수동 memoization을 기본값으로 삼지 않는다.
- `useMemo`, `useCallback`, `React.memo`는 측정된 렌더링 병목이 있거나, memoized child/context value/custom hook 반환값처럼 참조 안정성이 실제 계약인 경우에만 사용하고 이유를 설명한다.

| ✅ 올바른 예                                             | ❌ 잘못된 예                               | 이유                                     |
| -------------------------------------------------------- | ------------------------------------------ | ---------------------------------------- |
| `useMemo`로 `items`를 정렬한 뒤 `children` prop으로 전달 | 모든 컴포넌트에 `React.memo`를 기본으로 씀 | 측정되지 않은 최적화는 복잡성만 증가     |
| 측정 후 병목 컴포넌트에만 `memo` 적용                    | `useCallback`으로 모든 핸들러 감싸기       | 렌더링 비용보다 감싸는 비용이 클 수 있음 |

### 2. useEffect는 외부 시스템 동기화에만 쓴다

- 렌더링 가능한 값을 맞추기 위한 동기화 effect를 만들지 않는다.
- 외부 시스템: 브라우저 API, 이벤트 구독, 타이머, 외부 store 구독, 서버 동기화 등.

| ✅ 올바른 예                                                | ❌ 잘못된 예                                   |
| ----------------------------------------------------------- | ---------------------------------------------- |
| `useEffect`로 `window.addEventListener('resize', ...)` 구독 | `useEffect`로 prop 변경 시 상태 재계산         |
| `useEffect`로 외부 analytics 이벤트 전송                    | `useEffect`로 derived state 계산 후 `setState` |

### 3. 컴포넌트 형태와 조건부 렌더링

- React 컴포넌트는 `function ComponentName()` 선언을 기본으로 한다.
- 화살표 함수 컴포넌트는 HOC callback처럼 이름 없는 함수가 필요한 경우에만 사용한다.
- 조건부 렌더링은 가능한 한 early return을 사용하되, React Hook 호출 순서는 항상 보존한다.

```tsx
// ✅ 올바른 예
function ProductList({ products }: ProductListProps) {
  if (products.length === 0) {
    return <EmptyProductList />;
  }

  return (
    <ul>
      {products.map((product) => (
        <li key={product.id}>{product.name}</li>
      ))}
    </ul>
  );
}

// ❌ 잘못된 예: hook 호출 순서가 깨진다
function ProductList({ products }: ProductListProps) {
  if (products.length > 0) {
    const [page, setPage] = useState(1); // 조건부 hook 호출 금지
  }
  return ...;
}
```

### 4. props 타입과 상태 분리

- 재사용 가능한 컴포넌트는 명확한 props 타입을 가진다.
- props 타입은 인라인 객체 타입 대신 컴포넌트 위에 이름 있는 type alias로 분리한다.
- 상태와 그 상태를 사용하는 로직이 함께 생기면 커스텀 훅으로 분리한다.

| ✅ 올바른 예                                                                  | ❌ 잘못된 예                                                                                  |
| ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `type ProductCardProps = { product: Product; onAdd: (id: string) => void; };` | `function ProductCard({ product, onAdd }: { product: Product; onAdd: (id: string) => void })` |
| `useProductFilters` 훅이 상태와 handler를 담당                                | `ProductList` 본문에 50줄의 상태/핸들러/Effect가 모두 있음                                    |

## Verification

- `useEffect`가 외부 시스템 동기화인지 확인한다.
- memoization에 측정 근거가 있는지 확인한다.
- hook 호출 순서가 모든 경로에서 동일한지 확인한다.

pnpm lint
pnpm typecheck
pnpm build
