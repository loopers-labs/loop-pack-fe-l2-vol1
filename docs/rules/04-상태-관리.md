# 04 — 상태 관리

## When to read

React 상태, 전역 상태, URL 상태, 서버 상태, Suspense/Error boundary, 로딩/에러/empty 상태, persist/hydration을 설계할 때 읽는다.

## Rules

### 1. 상태의 출처에 따라 소유자를 정한다

| 상태 종류                                | 소유자          | 선택 이유                                        |
| ---------------------------------------- | --------------- | ------------------------------------------------ |
| 서버 데이터                              | TanStack Query  | 원본은 서버. 캐시로 snapshot을 관리한다          |
| URL에 복원/공유되어야 하는 조건          | nuqs            | 공유 링크, 새로고침, 앞뒤 이동으로 복원해야 한다 |
| 여러 페이지에서 공유되는 클라이언트 상태 | Zustand         | 비로그인 익명 상태의 임시 소유자                 |
| 한 화면의 일시적 UI 상태                 | React 로컬 상태 | 전역에 올리면 불필요한 리렌더와 복잡도만 증가    |

### 2. 파생은 상태로 저장하지 않는다

- 계산 가능한 값은 별도 상태로 중복 저장하지 않고 selector나 derived value로 계산한다.

| ✅ 올바른 예                                        | ❌ 잘못된 예                                                |
| --------------------------------------------------- | ----------------------------------------------------------- |
| `const totalCount = Object.keys(cart.items).length` | store에 `totalCount`를 따로 저장하고 action마다 갱신        |
| `const isOutOfStock = product.stock === 0`          | `isOutOfStock`을 서버 응답에 포함된 값을 그대로 상태로 저장 |

### 3. 서버 상태는 TanStack Query가 소유한다

- 서버 응답을 Zustand나 로컬 상태에 복사하지 않는다.
- `queryOptions`로 query key, queryFn, staleTime을 한곳에 모아 재사용한다.
- query key는 조건별로 정확히 분리한다.

```ts
// ✅ 올바른 예
export const productQueryOptions = (query: ProductListQuery) =>
  queryOptions({
    queryKey: ['products', 'list', query],
    queryFn: ({ signal }) => getProductList(query, signal),
    staleTime: 30_000,
  })

// ❌ 잘못된 예
const [products, setProducts] = useState([])
useEffect(() => {
  fetch('/api/products')
    .then((res) => res.json())
    .then(setProducts)
}, [])
```

### 4. URL 상태는 nuqs로 관리한다

- 검색·카테고리·정렬·페이지처럼 공유·새로고침·앞뒤 이동으로 복원해야 하는 조건은 nuqs로 관리한다.
- `history: "push"`로 각 변경을 앞뒤 이동에서 복원할 수 있게 한다.
- 페이지는 양의 정수만 허용해 그 외 값은 `1`로 정규화한다.

### 5. 전역 상태는 최소 구독으로 사용한다

- 컴포넌트는 필요한 값과 action만 selector로 선택해 구독한다.
- action은 별도 selector로 가져온다.

```ts
// ✅ 올바른 예
const count = useCartStore(cartSelectors.count)
const addToCart = useCartStore((state) => state.addToCart)

// ❌ 잘못된 예
const { items, addToCart, removeFromCart } = useCartStore() // 전체 store 구독
```

### 6. persist/hydration은 SSR을 고려한다

- Zustand persist 사용 시 `skipHydration: true`로 두고, 클라이언트에서만 `useHydratePersistedStore` 훅이 `store.persist.rehydrate()`를 호출한다.
- SSR HTML은 항상 빈 상태로 렌더하고 클라이언트 마운트 후 영속 상태를 끌어올린다.
- hydration mismatch가 발생하지 않도록 한다.

| 시점           | 서버 렌더                     | 클라이언트 렌더            |
| -------------- | ----------------------------- | -------------------------- |
| persist store  | 빈 상태                       | `rehydrate()` 후 영속 상태 |
| nuqs           | query string에서 초기값       | 사용자 상호작용으로 갱신   |
| TanStack Query | prefetch 후 dehydrate/hydrate | 캐시 수명에 따라 재조회    |

### 7. Suspense/Error boundary 라이브러리는 하나로 통일한다

- suspense boundary와 error boundary는 `@suspensive/react`의 `Suspense`, `ErrorBoundary`를 사용한다.
- `React.Suspense`, class 기반 error boundary, `react-error-boundary`를 새로 도입하지 않는다.
- TanStack Query의 suspense data fetching은 `@suspensive/react-query`의 `SuspenseQuery`, `SuspenseQueries`, `SuspenseInfiniteQuery` 컴포넌트를 우선 사용한다.
- `useSuspenseQuery`/`useSuspenseInfiniteQuery` 훅으로 suspense 발생 지점을 내부 컴포넌트에 숨기지 않는다.
- 이 프로젝트는 TanStack Query v5를 쓰므로 `@suspensive/react-query` import를 `@suspensive/react-query-5` npm alias로 설치한다.

| ✅ 올바른 예                                      | ❌ 잘못된 예                                       |
| ------------------------------------------------- | -------------------------------------------------- |
| `@suspensive/react`의 `Suspense`, `ErrorBoundary` | `import { Suspense } from 'react'`로 Suspense 사용 |
| `@suspensive/react-query`의 `SuspenseQuery`       | `useSuspenseQuery` 훅으로 suspense를 내부에 숨김   |

```tsx
// ✅ 올바른 예
<Suspense fallback={<ProductListSkeleton />}>
  <ProductList />
</Suspense>

// ❌ 잘못된 예: 훅이 내부에서 throw해 boundary 위치를 예측하기 어렵게 만듦
function ProductList() {
  const { data } = useSuspenseQuery(productQueryOptions(query));
  return ...;
}
```

### 8. 로딩/에러/empty 상태는 의미 단위로 처리한다

- 로딩은 suspense fallback으로, 에러는 error boundary로, empty는 데이터가 있는 컴포넌트 내부 early return으로 처리한다.
- `isLoading`, `isError`, `isFetching` 분기가 페이지 전체에 흩뿌려지지 않도록 한다.
- loading/error/empty 상태는 UI 변경 시 [`17-접근성.md`](17-접근성.md)의 체크리스트도 함께 확인한다.

| 상태  | 처리 위치                | 책임                   |
| ----- | ------------------------ | ---------------------- |
| 로딩  | `Suspense` fallback      | 해당 영역만 대체 UI    |
| 에러  | `ErrorBoundary` fallback | 복구/재시도 경로 제공  |
| empty | 데이터 컴포넌트 내부     | 사용자에게 안내 메시지 |

```tsx
// ✅ 올바른 예
function ProductListContent() {
  const products = useProducts();

  if (products.length === 0) {
    return <EmptyProductList />;
  }

  return (
    <ul>
      {products.map((p) => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}

// ❌ 잘못된 예: 상태 분기가 한 컴포넌트에 몰려 있음
function ProductList() {
  const { data, isLoading, isError } = useQuery(...);
  if (isLoading) return <Skeleton />;
  if (isError) return <Error />;
  if (!data?.length) return <Empty />;
  return ...;
}
```

### 9. Error boundary는 복구 경로를 제공한다

- 에러 발생 시 단순 메시지 대신 재시도 버튼, 폴백 콘텐츠, 안내 링크를 함께 제공한다.
- 서버 컴포넌트 에러와 클라이언트 컴포넌트 에러의 boundary 범위를 구분한다.

## Verification

- 상태 소유자가 데이터 출처와 수명에 맞는지 확인한다.
- selector가 최소한의 값만 구독하는지 확인한다.
- hydration mismatch가 발생하지 않는지 수동/자동 테스트로 확인한다.
- `@suspensive/react` 계열 컴포넌트를 사용하는지 확인한다.
- suspense fallback이 과도하게 넓지 않은지 확인한다.
- error boundary에 복구/재시도 경로가 있는지 확인한다.

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

UI 상태 변경은 [`17-접근성.md`](17-접근성.md)의 수동 체크리스트도 확인한다.
