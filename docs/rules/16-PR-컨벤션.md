# 16 — PR 컨벤션

## When to read

Pull Request를 작성하거나 리뷰할 때 읽는다.

## Source of truth

- PR 입력 필드: 저장소의 PR template
- 최소 설명 기준: 본 문서 Rules
- 커밋 규칙: [`15-Husky-품질-게이트.md`](15-Husky-품질-게이트.md)
- AI 생성 표기: [`14-주석-정책.md`](14-주석-정책.md)

## Rules

### 1. PR은 변경 의도와 검증 결과를 담는다

- PR 템플릿(이번 주 학습 / 피드백 받고 싶은 부분)을 채운다.
- "무엇을 바꿨는지"보다 "왜 바꿨는지"와 "어떻게 검증했는지"를 우선 설명한다.

| 항목      | 포함 내용                     |
| --------- | ----------------------------- |
| 변경 요약 | 어떤 문제를 해결하는지        |
| 주요 결정 | 구조/라이브러리 선택 이유     |
| 검증 방법 | 실행한 테스트, 수동 확인 항목 |
| 남은 위험 | 미실행 항목, 추후 작업        |

PR 본문에는 최소한 다음을 남긴다.

- 이번 변경의 설계 의도
- AI가 생성한 부분과 사람이 직접 검토·수정한 부분
- 실행했거나 의도적으로 생략한 검증 명령
- 강한 lint 규칙이 있다면 그 규칙을 둔 이유와 조정 가능성

### 2. PR은 메인 레포로 연다

- PR은 메인 레포(upstream)로 연다. 모두의 PR이 한곳에 모여 서로 리뷰할 수 있게 한다.
- fork에서만 머지하지 않고 upstream으로 보낸다.

### 3. AI 생성 부분은 명시한다

- AI가 생성한 부분과 직접 수정한 부분을 PR 설명이나 코멘트로 명시한다.
- 설명할 수 없는 코드는 제출하지 않는다.

| ✅ 올바른 예                                                          | ❌ 잘못된 예                         |
| --------------------------------------------------------------------- | ------------------------------------ |
| "장바구니 persist 로직은 AI가 생성했으며, hydrate 흐름은 직접 검증함" | AI 생성 코드를 아무런 표시 없이 제출 |
| "검색 debounce는 직접 구현, query key factory는 AI 보조"              | "다 AI가 했어요"                     |

### 4. 리뷰는 사실과 제안으로 한다

- 리뷰 코멘트는 문제가 무엇인지, 왜 중요한지, 어떻게 개선할 수 있는지를 함께 적는다.
- 단순히 "이상함"이라고만 하지 않는다.

| ✅ 올바른 예                                                                                                    | ❌ 잘못된 예       |
| --------------------------------------------------------------------------------------------------------------- | ------------------ |
| "이 selector가 전체 store를 구독하고 있어 Header가 불필요하게 리렌더됩니다. `cartSelectors.count`로 좁혀보세요" | "이거 최적화 필요" |
| "zod schema에서 `page`를 양의 정수로 제한하지 않으면 음수 URL이 들어올 수 있습니다"                             | "여기 이상함"      |

### 5. 머지 전 품질 게이트를 통과한다

- 변경 유형에 맞는 검증을 수행하고, 미실행 항목과 남은 위험을 보고한다.
- CI(`pnpm check`)가 통과해야 한다.
- 충돌이나 unresolved review 코멘트가 없어야 한다.

### 6. PR template 필수 항목

- PR template의 필수 항목을 채웠는지 확인한다.
- 실행한 명령과 의도적으로 생략한 명령이 구분되어 있는지 확인한다.
- AI 생성 부분과 직접 검토·수정한 부분이 드러나는지 확인한다.

## Verification

- PR 설명이 변경 의도와 검증 결과를 담고 있는지 확인한다.
- CI(`pnpm check`)가 통과하는지 확인한다.
- AI 생성 부분을 명시했는지 확인한다.

```bash
pnpm check
```
