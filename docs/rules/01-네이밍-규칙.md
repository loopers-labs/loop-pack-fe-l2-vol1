# 01 — 네이밍 규칙

## When to read

변수, 함수, 파일, 폴더, 타입, props, 이벤트 핸들러 이름을 지을 때 읽는다.

## Source of truth

- 파일명과 export 이름의 정적 제약: `eslint.config.mjs`
- 타입 이름과 사용 규칙: `tsconfig*.json`, `eslint.config.mjs`

## Rules

### 1. 이름은 의도를 드러낸다

- `data`, `temp`, `flag`, `value`, `info`, `stuff`처럼 맥락 없는 이름을 쓰지 않는다.
- 이름만 보고 무엇을 반환하는지, 어떤 동작을 하는지, 어떤 상태를 표현하는지 알 수 있어야 한다.
- boolean은 `is`, `has`, `can`, `should` 접두어로 의문 형태를 만든다.
- 함수는 동사구, 타입/컴포넌트는 명사구, 상수는 UPPER_SNAKE_CASE로 의도를 전달한다.

| ✅ 올바른 예         | ❌ 잘못된 예 | 이유                                 |
| -------------------- | ------------ | ------------------------------------ |
| `isAuthenticated`    | `authFlag`   | boolean 의도를 명확히 드러낸다       |
| `formatPriceToKRW`   | `moneyUtil`  | 무엇을 하는 함수인지 알 수 있다      |
| `ProductCardProps`   | `Props`      | 어떤 컴포넌트의 props인지 알 수 있다 |
| `EMPTY_CART_MESSAGE` | `emptyMsg`   | 상수임과 의미가 동시에 드러난다      |

### 2. 파일명은 대표 export 이름을 따른다

- 파일 하나에서보내는 대표 export와 파일명을 일치시킨다.
- default export는 Next 라우트, ESLint/Next 설정처럼 외부 도구가 요구하는 경우에만 허용한다.

| 종류           | 파일명                          | export                    |
| -------------- | ------------------------------- | ------------------------- |
| 타입           | `SelectOption.ts`               | `SelectOption`            |
| 컴포넌트       | `SelectTrigger.tsx`             | `SelectTrigger`           |
| 훅             | `useSelectRootState.ts`         | `useSelectRootState`      |
| namespace 유틸 | `OptionNavigation.ts`           | `OptionNavigation`        |
| 이벤트 핸들러  | `handleSubmit` inside component | 동작 의도가 드러나는 이름 |

### 3. React 규약은 이름에 드러난다

- 컴포넌트는 `function ComponentName()` 선언을 기본으로 한다.
- custom hook은 `use[A-Z0-9]...` 형태로 공개한다.
- 이벤트 핸들러는 `handleSubmit`, `handleIncrement`, `onOpenChange`처럼 동작 의도를 드러낸다.

| ✅ 올바른 예                     | ❌ 잘못된 예                                          |
| -------------------------------- | ----------------------------------------------------- |
| `function ProductCard() { ... }` | `const ProductCard = () => { ... }` (기본 컴포넌트로) |
| `useProductFilters()`            | `productFilters()`                                    |
| `handleAddToCart`                | `clickHandler`                                        |

### 4. boolean prop이 많아지면 구조를 나눈다

- `isPrimary`, `isDisabled`, `isLoading` 같이 boolean prop이 3개 이상 쌓이면 컴포넌트 분리나 compound component를 우선 검토한다.
- boolean prop 이름은 긍정형을 쓴다. `isNotVisible` 같은 부정형은 피한다.

| ✅ 올바른 예                          | ❌ 잘못된 예                      |
| ------------------------------------- | --------------------------------- |
| `variant="solid"` / `variant="ghost"` | `isSolid`, `isGhost`, `isOutline` |
| `status="loading"`                    | `isLoading`, `isPending`          |

## Verification

- 새 파일과 대표 export의 이름이 일치하는지 확인한다.
- 의도가 불분명한 이름이 있는지 리뷰한다.
- boolean prop이 과도하게 늘어나지 않았는지 확인한다.
