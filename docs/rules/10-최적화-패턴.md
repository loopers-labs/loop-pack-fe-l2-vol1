# 10 — 최적화 패턴

## When to read

렌더링 성능, 이미지/리소스 최적화, 번들 크기, 캐시 정책, lazy loading을 작성하거나 변경할 때 읽는다.

## Source of truth

- Next.js 이미지/성능 설정: `next.config.ts`, `package.json`
- React memo 규칙: [`./03-컴포넌트-라이프사이클.md`](./03-컴포넌트-라이프사이클.md)

## Rules

### 1. 측정하기 전에 최적화하지 않는다

- `useMemo`, `useCallback`, `React.memo`는 측정된 병목이 있거나 참조 안정성이 실제 계약인 경우에만 사용하고 이유를 설명한다.
- React DevTools Profiler, Lighthouse, 번들 분석기를 활용해 병목을 먼저 찾는다.

| ✅ 올바른 예                                     | ❌ 잘못된 예                                 |
| ------------------------------------------------ | -------------------------------------------- |
| Profiler로 확인 후 병목 컴포넌트에만 `memo` 적용 | 모든 컴포넌트에 `memo` 기본 적용             |
| `useMemo`로 context value 참조 안정성 보장       | `useCallback`으로 2줄짜리 핸들러 모두 감싸기 |

### 2. 이미지는 Next.js Image를 적극 활용한다

- 이미지는 Next.js `Image` 컴포넌트와 `sizes`, `priority`, `loading` 속성을 적극적으로 활용한다.
- 반응형 이미지 전달은 viewport별 최적화된 리소스를 사용한다.

| ✅ 올바른 예                             | ❌ 잘못된 예                             |
| ---------------------------------------- | ---------------------------------------- |
| `sizes="(max-width: 768px) 100vw, 50vw"` | `width`/`height` 없이 `img` 사용         |
| `priority`를 LCP 이미지에만 적용         | 모든 이미지에 `priority` 적용            |
| WebP/AVIF 포맷과 responsive delivery     | 원본 PNG를 모든 viewport에 동일하게 전송 |

### 3. API 응답 전에도 의미와 레이아웃을 제공한다

- semantic shell로 API 응답 전에도 의미와 주요 영역을 제공하고 최종 레이아웃의 geometry를 예약한다.
- skeleton은 실제 콘텐츠의 레이아웃을 미리 보여주어 CLS를 줄인다.

```tsx
// ✅ 올바른 예
function ProductDetailPage() {
  return (
    <main>
      <Suspense fallback={<ProductDetailSkeleton />}>
        <ProductDetail />
      </Suspense>
    </main>
  );
}

// ❌ 잘못된 예: 전체 페이지가 로딩 spinner로 덮임
function ProductDetailPage() {
  const { isLoading } = useQuery(...);
  if (isLoading) return <FullPageSpinner />;
  return ...;
}
```

### 4. 캐시 정책은 데이터 신선도와 재사용 범위에 맞춘다

- `staleTime`은 사용자가 얼마나 최신 데이터를 기대하는지, `gcTime`은 얼마나 오래 캐시를 유지할지로 결정한다.
- 동일 query key에 대해 일관된 캐시 정책을 적용한다.

| 데이터        | staleTime | 이유                      |
| ------------- | --------- | ------------------------- |
| 홈 섹션       | 60초      | 갱신 주기가 짧지 않음     |
| 상품 목록     | 30초      | 조건별 캐시와 짧은 재방문 |
| 상품 상세     | 5분       | 상대적으로 변하지 않음    |
| 사용자 프로필 | 1분       | 인증 상태 변화 반영       |

### 5. 번들과 초기 로드를 줄인다

- heavy 컴포넌트는 dynamic import로 코드 분할한다.
- third-party script는 `next/script`와 적절한 loading strategy를 사용한다.
- 초기 렌더에 필요 없는 데이터는 lazy fetch한다.

## Verification

- Lighthouse/Core Web Vitals 지표를 측정한다.
- 이미지 전송량과 LCP 변화를 확인한다.
- 캐시 정책이 조건별 query key에 일관되게 적용되는지 확인한다.

```bash
pnpm lint
pnpm typecheck
pnpm build
```
