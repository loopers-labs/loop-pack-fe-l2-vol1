# Week 09 Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 제공된 httpOnly 세션 API를 서버 렌더링 헤더, 안전한 로그인 복원, `/checkout`·`/orders` 보호 경로, 중앙 세션 만료 처리와 연결한다.

**Architecture:** 서버가 검증한 `session` 쿠키를 인증의 유일한 기준으로 삼는다. `proxy.ts`는 쿠키 존재 여부만 확인하고, 공용 서버 세션 코어가 서명·만료·사용자를 최종 검증한다. 로그인·로그아웃·주문 제출만 클라이언트 기능으로 두며 인증 사용자 원본을 Zustand에 복제하지 않는다.

**Tech Stack:** Next.js 16 App Router, React 19 Server/Client Components, TypeScript strict, Zustand 5, TanStack Query 5, Vitest 4, Testing Library, MSW, pnpm

**Spec:** `docs/superpowers/specs/2026-09-02-week09-auth-design.md`

## Global Constraints

- 패키지 매니저는 `pnpm`만 사용한다.
- 새 외부 의존성, `tsconfig`, Next 및 Vite 설정 변경은 이 계획에 포함하지 않는다.
- `@ts-ignore`, `eslint-disable`, 존재하지 않는 패키지 import를 사용하지 않는다.
- 모든 함수와 컴포넌트에 명시적 반환 타입을 작성한다.
- 컴포넌트는 named export로 만들고 파일당 하나만 둔다. Next.js의 `page.tsx` default export만 프레임워크 요구에 따라 예외로 둔다.
- 인증 사용자 원본을 Zustand나 Context에 저장하지 않는다.
- `/checkout`과 `/orders`만 필수 보호 경로로 둔다.
- 장바구니는 로그아웃 시 유지하고 주문 성공 시 초기화한다. 위시리스트는 로그아웃 시 초기화한다.
- 구현 단계의 Git stage·commit은 매번 정확한 파일과 메시지를 제시하고 사용자 승인을 받은 뒤 실행한다.
