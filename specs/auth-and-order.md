# 인증 · 주문 E2E 테스트 계획

대상: production 빌드로 구동 중인 commerce 앱 (`http://localhost:3000`), 한국어 UI.

공통 전제

- 모든 시나리오는 빈 상태(쿠키 없음 · 장바구니 비어 있음)에서 시작한다. 시나리오끼리 순서 의존이 없다.
- 계정은 `looper1@loopers.dev` ~ `looper8@loopers.dev`, 비밀번호는 모두 `looper1234`. 주문은 서버 메모리에
  계정별로 **누적**되므로 시나리오마다 다른 계정을 쓰고, 주문 건수(`총 N건`)를 단정하지 않는다.
- 시나리오 노브는 `scenario` 쿠키로 넣는다 (`context.addCookies([{ name: "scenario", value: "...", url: baseURL }])`).
  `expired` = me·orders 항상 401, `invalid` = login 항상 401, `error` = login·me·orders 500, `slow` = 1.5초 지연.
  `logout` 에는 노브가 적용되지 않는다.
- 헤더 기준 상태 판별: 미로그인은 `로그인` 링크, 로그인은 `루퍼N님` + `마이페이지` + `주문 내역` + `로그아웃`.
- 장바구니는 메모리 전용(persist 없음)이다. 장바구니를 유지해야 하는 단계는 전체 새로고침 대신
  링크 클릭(클라이언트 이동)으로만 이동한다.

### 1. 로그인과 접근 제어

**Seed:** `e2e-generated/seed.spec.ts`

#### 1.1 유효한 자격 증명으로 로그인하면 헤더가 로그인 상태로 바뀐다

**Steps:**

1. `/login` 으로 이동한다
2. "이메일" 입력란에 `looper1@loopers.dev` 를 입력한다
3. "비밀번호" 입력란에 `looper1234` 를 입력한다
4. "로그인" 버튼을 클릭한다

**Expected Results:**

- 홈(`/`)으로 이동한다 (`next` 파라미터가 없으므로 기본 복원 경로)
- 헤더에 `루퍼1님` 텍스트와 `마이페이지` · `주문 내역` 링크, `로그아웃` 버튼이 보인다
- 헤더의 `로그인` 링크는 더 이상 보이지 않는다

#### 1.2 미로그인 상태로 보호 경로에 들어가면 로그인 뒤 원래 경로로 돌아온다

**Steps:**

1. 쿠키가 없는 상태로 `/mypage` 로 이동한다
2. 주소가 `/login?next=%2Fmypage` 인 것을 확인한다
3. "이메일"에 `looper2@loopers.dev`, "비밀번호"에 `looper1234` 를 입력한다
4. "로그인" 버튼을 클릭한다

**Expected Results:**

- 2단계에서 `/login?next=%2Fmypage` 로 리다이렉트되고 "로그인" 제목과 로그인 폼이 보인다
- 로그인 후 `/mypage` 로 이동한다
- 마이페이지에 이름 `루퍼2` 와 이메일 `looper2@loopers.dev` 가 보이고, `주문 내역 보기` · `주문서로 이동` 링크와 `로그아웃` 버튼이 보인다

#### 1.3 비밀번호가 틀리면 오류 문구를 보여주고 로그인 상태로 바뀌지 않는다

**Steps:**

1. `/login` 으로 이동한다
2. "이메일"에 `looper3@loopers.dev`, "비밀번호"에 `wrongpassword` 를 입력한다
3. "로그인" 버튼을 클릭한다

**Expected Results:**

- `/login` 에 그대로 남는다 (이동 없음)
- `이메일 또는 비밀번호를 확인해주세요.` 가 alert 으로 보인다
- 헤더에는 여전히 `로그인` 링크가 보이고 `로그아웃` 버튼은 없다

#### 1.4 외부 URL 이 next 로 들어와도 그 주소로 보내지 않는다

**Steps:**

1. `/login?next=https%3A%2F%2Fevil.com` 으로 이동한다
2. "이메일"에 `looper4@loopers.dev`, "비밀번호"에 `looper1234` 를 입력한다
3. "로그인" 버튼을 클릭한다

**Expected Results:**

- 로그인 후 같은 오리진의 홈(`http://localhost:3000/`)으로 이동한다
- 주소에 `evil.com` 이 포함되지 않는다
- 헤더에 `루퍼4님` 이 보인다

### 2. 장바구니와 주문

**Seed:** `e2e-generated/seed.spec.ts`

#### 2.1 담기/담김 토글이 헤더 장바구니 수와 함께 움직인다

**Steps:**

1. `/products` 로 이동한다
2. 헤더의 `장바구니 0` 링크를 확인한다
3. "WOOD GLOVES 장바구니" 버튼을 클릭한다
4. 같은 버튼을 다시 클릭한다
5. 같은 버튼을 한 번 더 클릭한다

**Expected Results:**

- 3단계 후 버튼 텍스트가 `담기` → `담김` 으로 바뀌고 헤더 링크가 `장바구니 1` 이 된다
- 4단계 후 버튼 텍스트가 `담기` 로 돌아가고 헤더 링크가 `장바구니 0` 이 된다
- 5단계 후 다시 `담김` · `장바구니 1` 이 된다

#### 2.2 장바구니가 비어 있으면 주문서는 안내만 보여주고 주문 버튼이 없다

**Steps:**

1. `/login` 에서 `looper5@loopers.dev` / `looper1234` 로 로그인한다
2. 헤더의 `장바구니 0` 링크를 클릭한다

**Expected Results:**

- `/checkout` 으로 이동하고 "주문서" 제목이 보인다
- `장바구니가 비어 있어요` 와 `상품 목록에서 담기를 누르면 여기에 모여요.` 안내가 보인다
- `상품 보러 가기` 링크(`/products`)가 보인다
- `주문하기` 버튼은 존재하지 않는다

#### 2.3 담은 상품으로 주문하면 주문 내역으로 이동하고 장바구니가 비워진다

**Steps:**

1. `/login` 에서 `looper6@loopers.dev` / `looper1234` 로 로그인한다
2. 헤더의 `상품` 링크로 `/products` 로 이동한다
3. "WOOD GLOVES 장바구니" 버튼을 클릭한다
4. "네로 비니 블랙 장바구니" 버튼을 클릭한다
5. 헤더의 `장바구니 2` 링크를 클릭한다
6. 주문서의 상품 목록과 총 결제 금액을 확인한다
7. `주문하기` 버튼을 클릭한다

**Expected Results:**

- 5단계 후 `/checkout` 으로 이동하고 "주문 상품" 목록에 `WOOD GLOVES`(3,000원)와 `네로 비니 블랙`(49,000원)이 보인다
- `총 결제 금액 52,000원` 이 보인다
- 7단계 후 `/orders` 로 이동하고 "주문 내역" 제목이 보인다
- 방금 만든 주문 항목 안에 `WOOD GLOVES` 와 `네로 비니 블랙` 이 `수량 1` 로 보이고 `합계 52,000원` 이 보인다
- 헤더 링크가 `장바구니 0` 으로 비워진다
- 헤더에는 여전히 `루퍼6님` 이 보인다

#### 2.4 미로그인 상태에서 담은 장바구니가 로그인 뒤 주문서에 그대로 남는다

**Steps:**

1. 쿠키가 없는 상태로 `/products` 로 이동한다
2. "WOOD GLOVES 장바구니" 버튼을 클릭한다
3. 헤더의 `장바구니 1` 링크를 클릭한다
4. 로그인 화면에서 "이메일"에 `looper7@loopers.dev`, "비밀번호"에 `looper1234` 를 입력하고 "로그인" 버튼을 클릭한다

**Expected Results:**

- 2단계 후 미로그인 상태에서도 헤더가 `장바구니 1` 로 바뀐다
- 3단계 후 `/login?next=%2Fcheckout` 으로 리다이렉트되고, 이때도 헤더는 `장바구니 1` 을 유지한다
- 4단계 후 `/checkout` 으로 복원 이동한다
- 주문서에 `WOOD GLOVES` 와 `총 결제 금액 3,000원` 이 보이고 `주문하기` 버튼이 활성 상태다
- 헤더에 `루퍼7님` 이 보인다

### 3. 세션 만료와 로그아웃

**Seed:** `e2e-generated/seed.spec.ts`

#### 3.1 세션이 만료되면 만료 안내와 함께 로그인으로 보낸다

**Steps:**

1. `/login` 에서 `looper8@loopers.dev` / `looper1234` 로 로그인하고 헤더에 `루퍼8님` 이 보이는 것을 확인한다
2. `context.addCookies` 로 `scenario=expired` 쿠키를 넣는다
3. `/orders` 로 이동한다

**Expected Results:**

- 주소가 `/login?next=%2Forders&reason=expired` 로 바뀐다
- `세션이 만료되었어요. 다시 로그인해 주세요.` 가 alert 으로 보인다
- 헤더가 미로그인 상태(`로그인` 링크)로 돌아가고 `루퍼8님` · `로그아웃` 은 사라진다
- 브라우저 컨텍스트에 `session` 쿠키가 남아 있지 않다

#### 3.2 주문 중 세션이 만료되면 장바구니를 지키고 재로그인 뒤 주문서로 돌아온다

**Steps:**

1. `/login` 에서 `looper1@loopers.dev` / `looper1234` 로 로그인한다
2. 헤더의 `상품` 링크로 `/products` 로 이동해 "WOOD GLOVES 장바구니" 버튼을 클릭한다
3. 헤더의 `장바구니 1` 링크를 클릭해 주문서로 이동한다
4. `scenario=expired` 쿠키를 넣는다
5. `주문하기` 버튼을 클릭한다
6. `scenario` 쿠키를 제거한다
7. 로그인 화면에서 `looper1@loopers.dev` / `looper1234` 로 다시 로그인한다

**Expected Results:**

- 5단계 후 `/login?next=%2Fcheckout&reason=expired` 로 이동하고 `세션이 만료되었어요. 다시 로그인해 주세요.` 가 보인다
- 만료 화면에서도 헤더 링크는 `장바구니 1` 로 유지된다 (주문이 실패했으니 담은 것이 남는다)
- 7단계 후 `/checkout` 으로 복원 이동하고 `WOOD GLOVES` · `총 결제 금액 3,000원` 이 다시 보인다
- 헤더에 `루퍼1님` 이 보이고 `주문하기` 버튼이 다시 활성 상태다

#### 3.3 위조된 세션 쿠키는 만료로 처리한다

**Steps:**

1. `context.addCookies` 로 `session=garbage.tampered` 쿠키를 넣는다
2. `/mypage` 로 이동한다

**Expected Results:**

- 주소가 `/login?next=%2Fmypage&reason=expired` 로 바뀐다
- `세션이 만료되었어요. 다시 로그인해 주세요.` 가 alert 으로 보인다
- 헤더에 `로그인` 링크가 보이고 마이페이지 내용(이름/이메일)은 노출되지 않는다

#### 3.4 로그아웃하면 홈으로 나가고 보호 경로 재방문이 다시 로그인으로 튕긴다

**Steps:**

1. `/login` 에서 `looper2@loopers.dev` / `looper1234` 로 로그인한다
2. `/mypage` 로 이동한다
3. `로그아웃` 버튼을 클릭한다
4. `/orders` 로 이동한다

**Expected Results:**

- 3단계 후 홈(`/`)으로 이동하고 헤더가 `로그인` 링크만 보이는 미로그인 상태가 된다
- 브라우저 컨텍스트에 `session` 쿠키가 남아 있지 않다
- 4단계에서 `/login?next=%2Forders` 로 리다이렉트되고 주문 내역 데이터는 보이지 않는다
- 리다이렉트된 로그인 화면에는 `reason=expired` 안내가 없다 (정상 로그아웃은 만료가 아니다)

### 4. 오류 처리와 지연

**Seed:** `e2e-generated/seed.spec.ts`

#### 4.1 로그인 API 가 500 이면 오류 문구를 보여주고 로그인 화면에 남는다

**Steps:**

1. `context.addCookies` 로 `scenario=error` 쿠키를 넣는다
2. `/login` 으로 이동한다
3. "이메일"에 `looper3@loopers.dev`, "비밀번호"에 `looper1234` 를 입력한다
4. "로그인" 버튼을 클릭한다

**Expected Results:**

- `/login` 에 남고 이동하지 않는다
- `로그인에 실패했습니다.` 가 alert 으로 보인다
- 헤더에 `로그인` 링크가 유지된다 (로그인 상태로 바뀌지 않는다)
- `로그인` 버튼이 다시 활성화되어 재시도할 수 있다

#### 4.2 주문 내역이 500 이면 다시 시도 안내를 보여주고 로그인 상태는 유지한다

**Steps:**

1. `/login` 에서 `looper4@loopers.dev` / `looper1234` 로 로그인한다
2. `scenario=error` 쿠키를 넣는다
3. 헤더의 `주문 내역` 링크로 `/orders` 로 이동한다

**Expected Results:**

- `/orders` 에 머무른다 (로그인으로 튕기지 않는다 — 500 은 만료가 아니다)
- `주문 내역을 불러오지 못했어요` 와 서버 문구 `주문 정보를 처리하지 못했습니다.` 가 alert 으로 보인다
- `다시 시도` 버튼이 보인다
- 헤더에 `루퍼4님` 과 `로그아웃` 버튼이 그대로 보인다

#### 4.3 주문 요청이 500 이면 장바구니를 유지하고 오류 문구를 보여준다

**Steps:**

1. `/login` 에서 `looper5@loopers.dev` / `looper1234` 로 로그인한다
2. 헤더의 `상품` 링크로 `/products` 로 이동해 "WOOD GLOVES 장바구니" 버튼을 클릭한다
3. 헤더의 `장바구니 1` 링크를 클릭해 주문서로 이동한다
4. `scenario=error` 쿠키를 넣는다
5. `주문하기` 버튼을 클릭한다

**Expected Results:**

- `/checkout` 에 그대로 남는다
- `주문 정보를 처리하지 못했습니다.` 가 alert 으로 보인다
- 주문서에 `WOOD GLOVES` 와 `총 결제 금액 3,000원` 이 남아 있고 헤더는 `장바구니 1` 을 유지한다
- `주문하기` 버튼이 다시 활성 상태여서 재시도할 수 있다

#### 4.4 로그인 응답이 느리면 버튼이 진행 상태로 잠긴다

**Steps:**

1. `context.addCookies` 로 `scenario=slow` 쿠키를 넣는다
2. `/login` 으로 이동한다
3. "이메일"에 `looper6@loopers.dev`, "비밀번호"에 `looper1234` 를 입력한다
4. "로그인" 버튼을 클릭한다
5. 응답이 도착할 때까지 기다린다

**Expected Results:**

- 클릭 직후 제출 버튼 텍스트가 `로그인 중…` 으로 바뀌고 비활성(disabled)된다
- 이 동안 오류 alert 은 보이지 않는다
- 응답이 도착하면 홈(`/`)으로 이동하고 헤더에 `루퍼6님` 이 보인다
