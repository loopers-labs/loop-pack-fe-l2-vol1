# mutation testing (Stryker)

커버리지는 "테스트가 이 줄을 지났는가"를 본다. mutation testing은 "이 줄을 바꿨을 때 테스트가 빨개지는가"를 본다. 지나가기만 하고 아무것도 단언하지 않는 테스트를 찾는 도구다.

**점수를 올리는 게 목적이 아니다.** 살아남은 변형을 하나씩 보고 "이건 진짜 문제인가"를 가르는 게 목적이고, 그 판단은 도구가 대신 못 한다.

## 실행

```bash
pnpm test:mutation
```

`stryker.config.json`의 `mutate`에 대상 파일을 적는다. `pnpm check`에는 넣지 않는다 — 점수를 상시 게이트로 만들면 "판단한다"가 "숫자를 올린다"로 바뀐다.

**쓸 시점:** 단위 로직을 새로 쓰거나 고쳤을 때, 그 파일만 `mutate`에 넣고 한 번 돌린다.

## 1. 변형 대상 범위를 정한다

**단위 테스트로 덮인 로직만** 넣는다. 통합·E2E가 걸리는 파일을 넣으면 변형 하나마다 jsdom·MSW·브라우저가 뜬다.

넣을 것:

- 순수 계산 함수 (경계가 여럿인 것)
- 직접 쓴 parser·validator (라이브러리가 대신 안 지켜준다)
- 상태 전이, 저장·복원 로직

넣지 말 것:

- UI 컴포넌트, 페이지 조합 — 통합 테스트가 걸린다
- 테스트가 없는 파일 — 전부 `NoCoverage`로 뜨고 알려주는 게 없다
- 설정값·스타일 — 로직이 없다

범위를 정한 근거를 결과 문서에 남긴다. "왜 이 파일들인가"는 곧 "무엇을 단위로 볼 것인가"다.

## 2. 살아남은 변형을 세 종류로 가른다

전부 죽이려 들지 않는다. 살아남은 것마다 아래 중 하나로 분류하고 근거를 적는다.

| 분류          | 뜻                                 | 대응                            |
| ------------- | ---------------------------------- | ------------------------------- |
| **진짜 구멍** | 의미가 바뀌는데 테스트가 못 잡는다 | 단언을 보강한다                 |
| **동등 변형** | 어떤 입력으로도 결과가 안 바뀐다   | 왜 그런지 적고 둔다             |
| **범위 밖**   | 검증하기로 정한 공개 동작이 아니다 | 안 잡는 게 맞다는 근거를 적는다 |

**동등 변형인지 확인하는 방법:** 변형을 손으로 적용하고 전체 테스트를 돌린다. 통과하면 "테스트가 부족한 것"과 "죽일 수 없는 것"이 아직 구분되지 않은 상태다. 그 변형이 원본과 **다른 값을 내는 입력이 존재하는가**를 따져야 갈린다. 존재하지 않으면 동등 변형이다.

**범위 밖으로 미루기 전에 확인할 것:** 죽이려면 어떤 단언이 필요한지 먼저 써본다. 그 단언이 사용자에게 보이는 동작이 아니라 설정값·내부 구조를 고정하는 형태라면 범위 밖이 맞다. 단언을 안 써보고 "이건 중요하지 않다"로 넘기면 진짜 구멍을 놓친다.

## 3. 보강한 테스트가 실제로 죽이는지 확인한다

**통과하는 테스트를 추가했다고 변형이 죽는 게 아니다.** 보강 후 반드시 다시 돌려 그 변형이 `Killed`로 바뀌었는지 확인한다. 점수가 그대로면 못 죽인 것이다.

죽지 않았을 때 볼 것은 "단언이 원본과 변형을 **구분할 수 있는가**"다. 자주 걸리는 형태:

- 변형이 예외를 던지는데 프레임워크가 그 예외를 삼켜서, 결과가 원본과 같아진다
- 실패 경로와 성공 경로의 결과값이 우연히 같다 (둘 다 빈 배열·기본값)

둘 다 **초기 상태를 바꿔서** 갈린다. 빈 상태에서 시작하면 "복구됐다"와 "아무 일도 안 일어났다"가 같은 모양이다. 이미 값이 든 상태에서 시작하면 갈라진다.

이 저장소의 실제 사례는 `docs/week-08/advanced-result.md` §4에 있다.

## 4. 이 저장소 고유의 함정

- **샌드박스 복사** — Stryker는 프로젝트를 `.stryker-tmp/sandbox-*`로 복사한 뒤 그 안에서 테스트를 돌린다. `mutate`는 변형 대상일 뿐 복사 범위가 아니다. `.claude/skills`가 심볼릭 링크라 복사가 `ENOTSUP`로 죽는다 — `ignorePatterns`로 테스트와 무관한 디렉터리를 뺀 상태다. 새 디렉터리를 추가할 때 여기도 본다.
- **중단된 샌드박스** — 정상 종료하면 Stryker가 지우지만 중단되면 남는다. 남으면 `pnpm lint`가 샌드박스 안 복사본까지 검사해 깨진다. `.gitignore`와 `eslint.config.mjs` 양쪽에 넣어뒀다.
- **vitest `projects` 분리는 문제가 아니다** — Stryker의 vitest 러너가 변형 대상을 import하는 테스트만 골라 돈다. node/jsdom을 나누려고 별도 설정을 만들 필요 없다.
- **구현 파일에 도구 지시어를 넣지 않는다** — `// Stryker disable`로 변형을 끄지 않는다. 판단이 끝난 생존 변형은 결과 문서에 분류로 남긴다.
