# E2E 범위 검토

산출물은 후보별 근거와 작성자가 결정할 항목이다. 테스트 구현·무인 탐색·planner/generator 실행은 별도 요청 범위다.

## 1. 입력과 결정 출처

로그 원자료와 이벤트 정의, 사용자 흐름 후보, 관련 요구사항과 기존 범위 결정을 확보한다. 후보에 대응하는 통합 테스트와 지원 코드를 읽어 실행 환경·모킹 경계를 확인하고, 기존 E2E에서 중복 검증을 찾는다. 전달된 자료를 우선하고, 빠진 자료는 저장소나 연결된 문서에서 찾는다.

출처(경로·SHA 또는 자료 버전), 로그 기간·환경·스키마, 후보별 시작/종료 지점을 적으면 입력 확인이 끝난다. 현재 사용자 요구와 유효한 프로젝트 결정을 과거 예시보다 우선한다. 자료가 없거나 읽기가 잘렸다면 해당 항목을 **미검토**로 표시하고, 확보된 후보만 검토한다. 원자료 없이 기존 집계만 읽었다면 **재집계 미확인**으로 구분한다.

## 2. 로그 해석

각 수치에 단위·분자·분모·관측 한계를 붙인다.

| 확인할 것 | 판정 기준 |
| --- | --- |
| 세션과 이벤트 | 경로별 고유 세션 수로 빈도를 비교한다. 여러 이벤트를 묶은 경로는 세션의 합집합으로 센다. 세션을 사용자 수로 바꾸어 부르지 않는다. |
| 봇 추정 | 행동 패턴과 제외 근거를 기록하고, 단일 속성만으로 판단할 수 있는지 검토한다. 추정 제외 전후 세션 수와 순위를 비교한다. |
| 중복과 오류 | 동일 전송과 실제 반복 행동을 구별하는 기준·제거 건수를 남긴다. 오류 이벤트는 행동 순위와 분리하되 오류 세션과 실패 근거는 보존한다. |
| 비율과 흐름 | 전체/정제/시작 세션 중 어떤 분모인지 밝힌다. 다음 단계 도달은 같은 세션의 시간 순서와 관측 기간을 확인한다. 이탈 정의와 기간 끝에서 잘린 흐름의 한계를 적는다. 분모가 0이면 산출 불가다. |
| 실패 | 실패 이벤트 수/시도 수와 실패 경험 세션/시작 세션을 구별한다. 성공 미도달은 사용자 이탈도 포함한 대용 지표이며 기술 실패율과 구별한다. |
| 관측 범위 | 미계측 구간·로그와 현재 기능의 차이·수집 환경의 대표성을 적는다. 미계측을 0회 사용이나 실패 없음으로 해석하지 않는다. |

정제 전후 결과와 산식을 원자료에 대조하면 집계 검토가 끝난다. 식별자나 입력값을 보고서에 나열하기보다 집계값으로 근거를 남긴다. 이벤트 타입·발행 위치·민감 정보 등 **계측 코드 계약**은 기존 계약을 참조하며 여기서 다시 정의하지 않는다.

## 3. 후보별 테스트 경계

테스트 이름뿐 아니라 단언·렌더 헬퍼·mock을 읽고, 각 후보에서 실제로 관찰하는 사용자 결과를 적는다. 통합 테스트로 관찰하지 못하는 부분이 없으면 **없음**이라고 쓴다. 테스트 부재와 실행 환경의 관찰 불가능은 구별한다.

후보마다 다음 표를 채운다. 로그 근거가 부족해도 이미 확정된 필수 경로와 실패 비용은 별도로 검토할 수 있다.

| 후보·시작 → 종료 | 고유 세션/분모·비율 | 실패 비용·지표의 한계 | 기존 테스트가 보는 결과(파일·단언) | 통합 테스트로 못 보는 부분·재현 난도 | 제안·근거 |
| --- | --- | --- | --- | --- | --- |

제안은 **포함 유지 / 추가 후보 / 추가 제외 / 보류**로 구분한다. 빈도·실패 비용·통합 테스트에서의 재현 난도를 함께 판단하고 임의의 점수 곱으로 결정을 자동화하지 않는다. 실제 실행 경계 중 테스트가 대체하거나 생략하는 부분을 근거로 댄다. 기존 E2E가 그 경계를 다루면 추가 제외 근거에 연결한다. 현재 기능에 없는 경로는 검증 대상의 부재와 향후 요구사항을 구별해 판단한다.

모든 후보에 빈도·실패 비용·관찰 경계에 따른 제안과 근거 또는 보류 이유가 있으면 경계 검토가 끝난다. 빈도만으로 포함·제외를 결정한 후보가 있는지 확인한다.

## 4. 작성자 결정과 보고

보고에는 입력/미검토 범위, 집계 검토, 후보 표, 작성자 결정을 구분해 남긴다. 지적은 출처·근거·확실한 사실/추정을 표시한다.

기존 결정이 있으면 문서와 이유를 인용해 **기존 결정**으로 보존한다. AI 제안은 작성자의 확정과 분리하고, 새 선택이나 변경이 필요한 항목은 **작성자 결정 대기**로 남긴다. 기존 결정의 근거를 검토하는 요청은 새 승인을 요구하지 않고 끝낸다. 범위 확정 요청은 작성자가 선택·이유를 기록했을 때 완료하며, 단언과 구현은 그 다음 작업이다.
