# Review Rubric

## 1. 범위와 보존 조건

- 커밋이 한 가지 변경 이유를 가지는지 확인한다.
- 기존 동작, Source of Truth, 제외 범위를 바꾸는 diff가 섞였는지 확인한다.
- RFC의 예상 변경 파일과 실제 diff를 비교한다.

## 2. FSD 경계

- 하위 레이어가 상위 레이어를 import하는지 확인한다.
- 같은 레이어의 다른 슬라이스가 직접 협력하는지 확인한다.
- entity가 feature 또는 widget의 행위를 아는지 확인한다.
- shared가 화면 문구, 상품 정책, 비즈니스 상태를 소유하는지 확인한다.
- 조합 지점이 page 또는 widget에 있는지 확인한다.

## 3. Public API

- 외부 소비자가 슬라이스 루트만 import하는지 확인한다.
- 테스트가 내부 파일을 우회 소비하는지 확인한다.
- `index.ts`가 `export *` barrel이 아니라 명시적 계약인지 확인한다.
- 문서에 기록된 Public API 수와 실제 루트가 일치하는지 확인한다.

## 4. 데이터와 에러 경계

- 서버, URL, Zustand, 로컬 상태의 Source of Truth가 중복되지 않는지 확인한다.
- query key와 fetch가 같은 조건 객체를 사용하는지 확인한다.
- 에러 분류 표, `throwOnError`, fallback, 회귀 테스트가 같은 기준인지 확인한다.
- 재시도 불가능한 실패에 동작하지 않는 버튼을 노출하지 않는지 확인한다.
- route `error.tsx`의 `reset()`과 Query 오류 초기화가 실제로 연결되는지 확인한다.

## 5. 변경 반경과 문서

- 삭제 시나리오에서 삭제 파일과 살아남아 수정할 소비자를 구분한다.
- 소비자를 테스트 제외/포함으로 나눴다면 이유를 기록했는지 확인한다.
- 결정 번복 후 요약, 표, Validation, Rejected 절에 낡은 결론이 남았는지 확인한다.
- 검증을 수행했다는 문장이 실제 테스트 또는 실행 기록으로 뒷받침되는지 확인한다.

## 심각도

- **Blocker**: 의존 방향, 상태 중복, 기능 손상, 거짓 검증 주장
- **Major**: Public API 우회, RFC와 구현의 확정 결론 불일치, 복구 불가능한 오류 UX
- **Minor**: 근거 누락, 재현 절차 미완료, 유지보수상 혼동
- **Nit**: 의미나 동작에 영향이 없는 표현과 형식
