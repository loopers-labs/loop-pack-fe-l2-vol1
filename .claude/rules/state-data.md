# 상태 · 데이터 규칙

## 원본의 위치가 도구를 정한다

상태를 하나 만들 때마다 네 칸을 채운다 — **원본 · 수명 · 공유 범위 · 사용자가 바뀌면 어떻게 되는가.** 도구는 원본이 정한다.

| 계층 | 원본 | 도구 |
| --- | --- | --- |
| 서버 상태 | 서버 DB | Query 캐시 |
| URL 상태 | 주소창 | URL parser |
| 클라이언트 상태 | 브라우저 메모리 | store · 컴포넌트 state |

- 위에서부터 **소거**한다. 서버에 맡기고, URL에서 빌리고, 남은 것만 담는다. 전역 store는 첫 선택지가 아니라 마지막 잔여물이다.
- 고른 자리를 **수명**(언제까지 살아야 하나)과 **공유 범위**(누가 읽나)로 검증한다. 분류 표는 정답지가 아니라 양식이고, 근거 칸이 본체다.
- 뷰와 상태 사이에 어댑터를 한 겹 둔다 — 쿼리 팩토리 · URL parser · selector 훅. 컴포넌트는 상태의 소유자가 아니라 **구독자**다.

## 서버 상태는 내 상태가 아니라 캐시다

- `queryKey`는 `queryFn`의 의존성이다. 키가 바뀌면 다시 가져오고 같으면 캐시를 쓴다 — 이걸로 요청 순서와 도착 순서가 어긋나는 문제가 끝난다. `queryFn`이 읽는 값은 키에 다 들어 있어야 한다.
  - 브라우저가 자동으로 싣는 쿠키는 예외다. 그 대응은 키가 아니라 세션이 바뀔 때 캐시를 통째로 교체하는 것이다.
- 키 계층(`all → list → detail`)을 뼈대로 `queryOptions` 팩토리를 도메인마다 두고 화면은 그것만 쓴다. API가 바뀌면 고칠 곳이 하나고, 캐시 정책과 테스트 경계가 거기 모인다.
- 캐시에는 시계가 둘이다 — `staleTime`(언제까지 신선한가)과 `gcTime`(언제까지 남아 있나). 그 데이터가 얼마나 오래 맞는지로 정하고, 팩토리 기본값을 상속받는 것도 선택이다.
- 조건 → 키 변환 함수는 한 벌만 둔다. 서버 선조회와 브라우저가 그 함수를 같이 써야 키가 갈라지지 않는다.
- 계정 소유 데이터는 키에 사용자 식별자를 넣고 계정 범위임을 표시한다. 계정이 바뀌면 키가 갈린다.
- 세션이 바뀌면 그 표시를 따라 **취소 → 계정 캐시 제거 → 사용자 교체** 순서로 정리한다. 진행 중인 계정 조회를 먼저 끊지 않으면 늦게 온 응답이 새 세션 화면에 이전 계정 데이터를 그린다.

## 낙관적 갱신은 캐시를 잠깐 빌리는 것이다

- **빌리고(`onMutate`) · 되돌리고(`onError`) · 돌려주고(`onSettled`)**. 빌리기 전에 진행 중인 조회를 취소해 그 응답이 빌린 캐시를 덮지 않게 한다.
- 무효화는 기다린다. 기다리지 않으면 재동기화가 끝나기 전에 로딩 표시가 먼저 사라져 사용자가 옛 값을 확정된 값으로 본다.
- 낙관이 정당화되는 화면은 **롤백이 화면 안에서 끝나는** 곳이다. 돈·재고·알림까지 되돌려야 하면 낙관하지 않는다.

## URL 상태

- parser가 허용값과 타입을 보장한다. 잘못된 값은 기본값으로 떨어지고 화면은 그 결과만 쓴다.
- 입력 중인 값은 로컬에 두고 **확정된 값만 URL로 승격**한다. 조회는 승격된 값으로만 한다.
- 사용자가 한 이동은 히스토리에 남기고, 시스템 보정은 남기지 않는다.
- 결과 집합을 바꾸는 조건이 변하면 페이지를 1로 되돌린다.

## 클라이언트 상태에 담기 전에

- **서버 상태를 복사하지 않는다.** 응답을 store에 담으면 원본이 둘이 되고, 무효화는 Query 캐시만 갱신한다. 담을 것은 식별자와 사용자가 고른 값뿐이다.
- **파생값을 저장하지 않는다.** 개수는 목록에서 계산한다. 저장하면 둘을 항상 같이 갱신해야 한다.
- 구독은 그 컴포넌트가 쓰는 조각까지 좁힌다. 목록 전체를 구독하고 안에서 하나만 꺼내면 남의 변경에도 다시 렌더된다.

## 저장해 두는 상태

- 저장값은 남이 고칠 수 있는 입력이다. 읽을 때 형태를 검증하고, 깨진 값은 초기 상태로 시작한다.
- `version`을 올리면 `migrate`를 함께 쓴다. 현재 버전의 형태 지식은 검증에, 과거 버전 지식은 migrate에 각각 한 곳씩 둔다.
- 복원은 첫 렌더 뒤에 시작해 서버 HTML과 어긋나지 않게 한다. **복원 전**과 **값이 없음**은 다른 상태이므로 화면에서 구분해 그린다.
- 계정 범위 데이터가 기기 저장소에 남는다. 사용자가 바뀔 때 남길 값인지 지울 값인지 정한다.

## 서버가 채우고 클라이언트가 이어받는다

- 캐시는 사용자 한 명의 것이다 — 서버는 요청마다 QueryClient를 새로 만들고, 브라우저는 문서 수명 동안 하나를 유지한다. 렌더 중 만들면 리렌더마다 캐시가 초기화된다.
- 서버가 채운 캐시는 hydration 경계로 넘기고 클라이언트는 같은 키로 이어받는다. 같은 데이터를 양쪽에서 두 번 조회하지 않는다.
- 메타데이터와 본문이 같은 데이터를 쓰면 서버 호출 수를 센다. 브라우저 Network에는 보이지 않는다.
- 메타데이터 조회가 실패하면 상위 메타데이터를 상속하게 둔다. **결과 0건**과 **조회 실패**는 다른 화면이고 다른 메타데이터다.
- 프레임워크 캐시와 Query 캐시가 같은 데이터를 들고 있으면 무효화 시점을 각각 적는다. 한쪽만 지우면 새로고침에서 옛 값이 돌아온다.

## 예외

`app/api/**`는 네트워크 건너편의 mock 백엔드라 이 규칙으로 판정하지 않는다.
